## Overview

本文件是基于官方公开资料整理的独立分析，不是 Arco Design 官方发布的 DESIGN.md。研究日期为 2026-10-10。实现基线固定为 `@arco-design/web-react` 2.66.16、官方 `main` 提交 `c2b050d9c7ce94bebba94f616a0721344231caac`；官方 AI Skill 固定为提交 `47b174eb9c5866db3d1de20bd4a4ce5f2541eb8a`。这些是研究快照，不意味着以后读取本文件时仍是最新版本。[实现基线](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/package.json)

Arco 的设计语言围绕务实的任务效率与可扩展的表达展开：中性色承托密集信息，蓝色指向操作与选择，紧凑控件、细分隔和重复的对齐关系建立工作节奏。适用场景包括运营后台、管理控制台、业务表单、数据表格、资源详情和监控面板。不要把这些工作界面自动改造成带大幅宣传标题、装饰渐变和大量营销卡片的首页。

四项价值在页面生成中转译如下；右侧为本分析的可执行约束，并非官网原文：

| 价值 | 页面生成约束 |
| --- | --- |
| Clear（清晰） | 先显示页面标题与当前范围，再放查询、主操作和结果；提交错误落在相应字段下，同时说明修复方法。 |
| Consistent（一致） | 同一页面的 Button、Input、Select 使用相同 size；同类列表保持列名、状态标签和操作文案相同。 |
| Rhythmic（韵律） | 重复卡片采用相同内边距与标题位置；表格同列对齐，表单标签和输入起点形成连续竖线。 |
| Open（开放） | 业务需求超出默认值时，通过主题变量、组件 props 与已记录的扩展令牌调整，保留状态关系和接口语义。 |

价值依据为官方[设计价值观](https://arco.design/react/docs/spec/values-of-arcodesign)与[设计哲学](https://arco.design/react/docs/spec/philosophy)，可核查的对应官网源文件列在 Reference Sources。

读取约定：文件起始的 `---` 包围标准 YAML。`version` 是本分析的文档版本；`provenance.implementation.packageVersion` 才是组件包版本。令牌引用使用单层花括号与点路径；组件状态采用独立条目，不隐式继承。`typography` 引用代表整套文字属性，颜色引用代表一个颜色值。`source` 指向同一提交下的源码路径；`origin: analysis-policy` / `analysis-role-mapping` 表示本分析补充；`source-composition` 表示由源码已有参数组合出的语义角色。

`tokenScope` 标明适用子区域：例如 Table 为 cell 与外框、Checkbox 为标记与标签、Skeleton 为占位行与图片，不能把所有字段直接涂到根节点。组件令牌是静态分析数据，不是可以直接传给组件的 React props，也不是声称遵循某个正式令牌交换标准。生成器须先解析引用，再将 `textColor` 转成 CSS `color`、`rounded` 转成 `border-radius`，同时按 `api` 使用实际组件。根目录存在 DESIGN.md 不保证每个工具都会自动读取，应在生成任务中明确指定本文件。

## Colors

### 基础色板与主色状态

Arco Blue 为 `colors.arcoblue` 的 1–10 阶，不要与另一个基础色板 `blue` 混淆。下表为当前默认浅色主题的主色映射，读取语义状态而非根据深浅猜测动作：

| 状态 | 对应色阶 | 值 | 用途 |
| --- | --- | --- | --- |
| default | Arco Blue 6 | {colors.primary.default}（#165DFF） | Primary Button 实底、控件聚焦边框、进度条、选中操作文字。 |
| hover | Arco Blue 5 | {colors.primary.hover}（#4080FF） | Primary / Outline 按钮悬浮；不自动用于所有蓝色文字。 |
| active | Arco Blue 7 | {colors.primary.active}（#0E42D2） | Primary / Outline 按钮按压。 |
| disabled | Arco Blue 3 | {colors.primary.disabled}（#94BFFF） | Primary 禁用底、Outline 禁用字与边框、已选 Checkbox / Radio 禁用底。 |
| light | Arco Blue 1 | {colors.primary.light}（#E8F3FF） | 信息 Alert、选中页码等浅色背景。 |

`light1`–`light4` 分别保留 1–4 阶，防止误把所有浅底状态压成一个值。以上 disabled 是主要操作组件的基线，不能推出所有蓝色禁用文本都是相同背景。源码状态依据为 [Button token.less](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/Button/style/token.less)。

| Link | arcoblue | {colors.link.default} | {colors.link.hover} | {colors.link.active} | {colors.link.disabled} | {colors.link.light} |

Success、Warning、Danger 的 hover / active 指实底与描边操作的 5 / 7 阶，并不规定状态图标、Alert 或 Tag 的文字也变色。默认 Link 在悬浮与按压时文字仍保持 6 阶，背景分别切换到 {colors.fill.level2} 和 {colors.fill.level3}。Text Button 同样保持主色文字，用填充变化表达交互。[Link 源码](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/Link/style/token.less)

警告采用 orange-6（#FF7D00），不是 gold-6。成功、风险和错误必须同时出现文案或语义图标；不要只依靠色彩区分订单、任务或资源状态。

### 中性色与界面层次

| 层级 | 文字 | 填充 | 边框 |
| --- | --- | --- | --- |
| 1 | {colors.text.level1} 标题、正文 | {colors.fill.level1} 轻背景、行悬浮 | {colors.border.level1} 弱分隔 |
| 2 | {colors.text.level2} 常规说明与次一级内容 | {colors.fill.level2} 默认输入、次按钮 | {colors.border.level2} 容器与标准分隔 |
| 3 | {colors.text.level3} 辅助信息、占位提示 | {colors.fill.level3} 控件悬浮 | {colors.border.level3} 强于普通分隔的边框 |
| 4 | {colors.text.level4} 禁用信息 | {colors.fill.level4} 更强填充、关闭的 Switch | {colors.border.level4} 高强调边框 |

四级文字并非所有情况都满足可访问性对比度；关键正文、金额、错误说明和必要表单标签不得使用四级文字。最终项目需在实际字体、背景和尺寸下检测对比度。

源码 `color-bg-1`–`color-bg-5` 在浅色下全是白色：{colors.surface.page}、{colors.surface.container}、{colors.surface.nested}、{colors.surface.raised}、{colors.surface.popup}。角色分离不代表一定有色差。`dashboardCanvas` 是基于 gray-1 的本分析页面建议 {colors.surface.dashboardCanvas}，不是把源码 `color-bg-1` 宣称为灰色。选择工作台灰底时明确启用此角色，卡片仍用 container。

Tooltip 使用 {colors.surface.tooltip} 与 {colors.onSolid}；Popover / Select 使用 popup。遮罩为 {colors.surface.mask}，即原始 #1D2129 的 60% 透明度，不能把它当作预混合后的实色。[主题角色定义](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/style/theme/global.less)

### 数据可视化

`colors.data.series1`–`series20` 是源码 `color-data-1`–`color-data-20` 的有序映射，来源顺序为 arcoblue-5/3、blue-5/3、orange-6/3、green-4/3、purple-4/3、gold-6/4、lime-6/4、magenta-4/3、cyan-6/3、pinkpurple-4/2。它是界面主题提供的图表色序，不表示某个独立图表库的所有内置配色。

本分析约束：同一业务系列在筛选、刷新、排序及跨图表时保持颜色映射；分类图按该顺序分配。超出 20 个系列先聚合次要系列，再使用标记或线型区分，不随机生成新颜色。连续数值不要套用分类色序，应选同一基础色板由浅到深，并显式标注量纲。图例、标签或标记至少保留一种，颜色不承担唯一识别信息。

### 深色主题与机器映射

深色主题不是浅色反相。页面用 {colors.dark.surface.page}，一级容器用 {colors.dark.surface.container}，二级容器与 Modal / Drawer 用 {colors.dark.surface.nested}，三级容器用 {colors.dark.surface.raised}，浮层用 {colors.dark.surface.popup}。边框基础色 {colors.dark.borderDefault} 与四级边框系列是不同变量，不能互相替代。

暗色四级文字分别为 {colors.dark.text.level1}、{colors.dark.text.level2}、{colors.dark.text.level3}、{colors.dark.text.level4}，保留白色的 90% / 70% / 50% / 30% alpha。四级填充保留 4% / 8% / 12% / 16% alpha。四级边框仍经 neutral-2/3/4/6 读取暗色色板；源码没有把它们全部改成半透明白色。

`colors.dark.primary` 保留暗色色板的 6 / 5 / 7 阶状态；暗色 light1–4 则是主色 6 阶的 20% / 35% / 50% / 65%，不是暗色色板的 1–4 阶。禁用 primary 使用 light3 的 50% alpha。`themes.dark.colorOverrides` 按完整路径重绑定颜色引用；代码工具先选择主题，再递归解析组件颜色。不要对 hex 做自动反色。数据色也使用对应暗色色板值。

`colors.onSolid` 是 Button 与 Tooltip 源码中写死的纯白；`colors.white` 对应可随暗色变成 90% 白的 CSS 变量；Switch 滑块使用独立 `bgWhite`（暗色为 #F6F6F6）。这三者不可合并。

8 位十六进制按 CSS `#RRGGBBAA` 编码，alpha 转换到 8 位通道时存在最多半个通道的量化误差。实现 Arco 时优先使用官方 CSS 变量保留精确百分比；本文件不把透明色预先与某一种背景合成。[深色变量覆盖](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/style/theme/css-variables.less)

## Layout

源码基础尺寸采用 4px 阶梯（`size-1`–`size-50`），尺寸与间距是两个体系。`spacing` 保留源码完整 23 个值：0、2、4、6、8、10、12、16、20、24、32、36、40、48、56、60、64、72、80、84、96、100、120px。不能把间距刻度误写成只有 8px 的倍数。[全局刻度](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/style/theme/global.less)

默认 Button、Input、Select、Radio.Button 的高度为 32px；mini / small / large 为 24 / 28 / 36px。不是所有组件都高 32px：Checkbox / Radio 标记 14px、Switch 高 24px、Tag 默认高 24px、Menu 纵向项高 40px、line Tabs 高 40px。组件外部点击区域与可见标记尺寸分开处理。

Grid 使用 24 栏；同一行的 `span` 和占位总数最多 24，需要换行时建立下一行。用 `Grid.Row`、`Grid.Col` 与 `gutter`，避免同一内容区域同时建立互相冲突的手写宽度系统。源码 Row 的默认 gutter 为 0，24px 只是本分析工作页面建议，并非组件默认值。[Grid 实现](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/Grid/row.tsx)

本分析的中后台布局基线：

- 宽度 ≥992px：页面内边距 24px，主要模块纵向间隔 24px，网格 gutter 24px。内容随可用宽度伸展，不套用统一的营销站最大宽度。
- 576–991px：页面内边距 16px，模块间隔 16px，网格 gutter 16px；将次要横向工具移入 Dropdown。
- ≤575px：页面内边距 12px，模块间隔 16px，网格水平 gutter 8px、纵向 16px；单列内容保持顺序。
- 表单默认 Form.Item 下间距 20px，垂直标签与输入间隔 8px；与整个模块的 24px 间距区分。
- 带边框 Card 内容使用 16px 内边距，Table 单元格使用 9px 16px；嵌套 Table 时避免同时堆叠两层大内边距。

Layout.Sider 的源码默认展开宽 200px、折叠宽 48px；220px/60px 是官方 Skill 示例的配置值，不是组件默认。建议显式设置 `width`、`collapsedWidth` 与 `breakpoint`，按长菜单实际测量后选择。[Sider 默认值](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/Layout/sider.tsx)

## Elevation & Depth

源码提供三级常规阴影，并各有中心、上、下、左、右与对角方向；YAML 保留向下的代表值。层级与组件事实分开：

| 层级 | 阴影代表值 | 采用方式 |
| --- | --- | --- |
| none | none | 普通 Card、Modal 源码默认不统一添加浮起阴影。 |
| special | 0 0 1px，黑色 30% | 源码特殊细阴影；不用于所有容器。 |
| 1 | 0 2px 5px，黑色 10% | popup-box-shadow-base 的全局默认，不自动覆盖各组件的实际阴影。 |
| 2 | 0 4px 10px，黑色 10% | Select Popup、Popover、Message、Tooltip 等。 |
| 3 | 0 8px 20px，黑色 10% | 可用于明确需要更高强调的扩展场景，先检查目标组件实际实现。 |
| 4 | 未定义，YAML 为 null | 官网文字提到四层，但当前 global.less 没有 shadow4；不得编造数值。 |

阴影用可解析的 8 位黑色表达，保留 alpha；这些是空间提示，不是业务状态。表格固定列的 inset 阴影另有实现，不应被上述 drop shadow 替换。Card 的 `hoverable` 也有专门阴影色，默认 Card 不需要加该交互。[阴影源码](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/style/theme/global.less)

层叠顺序：Affix 999，常规 Popup 1000，Drawer / Modal 1001，Message / Notification 1003。不要每新增浮层就把 z-index 提升到任意大数；相同层级依赖 DOM 与 Portal 的顺序，嵌套弹层需单独验证遮罩和焦点行为。

## Shapes

{rounded.none}、{rounded.small}、{rounded.medium}、{rounded.large}、{rounded.circle} 对应 0、2、4、8px、50%。额外的 {rounded.progress-track} 为 Progress 样式中的 100px 胶囊轨道圆角，仅用于对应子区域。Button、Input、Select 触发器、Tag、Menu、Tooltip、带边框 Card 默认使用 2px；Select Popup、Popover、Modal 和 Table 外框使用 4px；8px 是可用的全局大圆角，不是所有卡片的默认圆角。

默认 Switch 的 track 使用 12px 半径，滑块使用 50%；14px Radio 使用 50%。YAML 中 Switch 的 `rounded` 表达形态，生成实际 track CSS 时使用其 `trackRadius`，不能对 40×24px 轨道机械使用 50% 导致椭圆形状。

细边框通常为 1px；Checkbox / Radio 标记边框是 2px。透明边框同样参与尺寸计算，不可直接删除后导致状态切换位移。图标从 `@arco-design/web-react/icon` 使用；操作图标须有可访问名称，不能用装饰图形替代功能语义。

## Motion

`motion.duration` 对应 default.less 的 100、200、300、400、500ms 与 1000ms loading 时长。Skeleton 的实际动画周期另为 1500ms。`motion.easing` 完整保留源码曲线：

| 类型 | 曲线 | 规则 |
| --- | --- | --- |
| linear | cubic-bezier(0, 0, 1, 1) | 简单颜色变化、循环动画；遵循组件默认。 |
| standard | cubic-bezier(0.34, 0.69, 0.1, 1) | 一般状态或布局过渡的默认候选。 |
| overshoot | cubic-bezier(0.3, 1.3, 0.3, 1) | 仅用于有明确反馈目的的强调，不能给每张卡片弹跳。 |
| decelerate | cubic-bezier(0.4, 0.8, 0.74, 1) | 进入过渡的候选曲线。 |
| accelerate | cubic-bezier(0.26, 0, 0.6, 0.2) | 退出过渡的候选曲线。 |

以上类型名称与数值来自源码；“候选”的用途描述是本分析建议，不代表每个组件一定使用该曲线。[动效变量](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/style/theme/default.less)

生成规则：优先让组件实现自身动效，不再给父容器叠加相同过渡。自定义颜色反馈先选 100ms linear，自定义模块显隐先选 200ms standard；超过 300ms 的普通操作过渡需说明目的。只动画 transform、opacity 或必要的颜色属性，避免整个 Table 使用 `transition: all`。请求状态必须依据真实请求结束，不用固定动画时长假装成功。

本分析补充 `prefers-reduced-motion: reduce` 策略：关闭循环 Skeleton 的位移动画，保留静态占位；自定义位移和缩放过渡取消或缩短，保留状态变化与完成反馈。这不是当前源码对所有组件的统一保证，需要在实现中主动接入。

## Components

组件默认尺寸与颜色来自各自 `token.less`；少数宽度、轨道尺寸来自组件 TSX，YAML 使用 `implementationSource` 标明。除 `overrideOnly` 的尺寸补丁外，每个状态条目包含完整背景、文字、边框、排版、圆角、内边距、高度和宽度，不依赖“套用上一行”这样的隐式规则。`auto` / `100%` 表达内容自适应；不要据此编造固定尺寸。

### 操作与输入

Button 的 primary 表示当前操作组的主要动作，secondary 表示取消和辅助动作，outline 表示需轮廓强调的动作，text 用于表格行操作或轻量动作。danger 是 `status="danger"` 与 type 的组合，实际 API 没有 `type="danger"`。本文件 `button-danger` 明确指 primary + danger，并另列 secondary / outline / text 的危险状态。

同一操作组最多一个实底主按钮，使用 {components.button-primary}；删除等危险操作采用 {components.button-danger-outline} 或 {components.button-danger-text}。只有独立危险确认弹窗中的最终确认才优先用 {components.button-danger}。disabled 切换到相应独立状态令牌；不允许仅降低整个按钮 opacity 来模拟。loading 与禁用是不同状态，由官方组件处理 spinner 和重复提交限制。

Input / Select 的默认背景是二级填充、透明边框；hover 为三级填充，focus 为 container 背景和主色边框，focus 阴影扩散尺寸为 0。错误默认浅红底，错误 focus 为 container 与危险色边框。不得将当前默认描述为“白底灰边框”。Input 的单独输入默认垂直 padding 经公式四舍五入为 4px；Select 单选 view 将 12px padding token 减去 1px 边框得到实际 11px，line-height 为 30px，YAML 已记录。带前后缀、附加控件、多选等区域保留组件原样式。选中 Select.Option 默认文字是一级、字重 500，背景仍为 popup，不自动套成蓝底白字。

Checkbox 多选，Radio 单选，Switch 用于即时生效的二元设置。使用 visible label；保留 checked、indeterminate、disabled、loading 的真实语义。Form.Item 用 `field`，在 Form 内绑定 Switch / Checkbox 时核对 `triggerPropName="checked"`；受控组件使用 value/checked + onChange。错误说明在字段下方，用具体修复动作；保留用户的无效输入直到其修正，不静默转换成另一合法值。[官方 Form Skill](https://github.com/arco-design/arco-design-skill/blob/47b174eb9c5866db3d1de20bd4a4ce5f2541eb8a/skills/arco-design/references/components/data-entry/form.md)

### 导航与数据

Tag 表达已存在的分类或状态，不代替页面主要按钮；默认 24px 高、12px/500。Tabs 用于同一上下文的并列内容；Menu 用于页面导航；Breadcrumb 用于路径；PageHeader 承担当前页标题、说明、返回和主要操作。Menu 选中默认是二级填充 + 主色文字，并非所有选中行都是 primary-light-1。

Pagination 默认页码区域为 32×32px，选中为主色浅底和主色字。分页改变时保留筛选条件，回显当前总数和范围；过滤后复位页码与数据请求应保持一致。Card 组织内容，不为每一个数值单独生成带阴影卡片。Table 保留标题、排序、选择和操作的稳定列位置；默认 cell padding 是 9px 16px，行高随多行内容增大。需要紧凑尺寸时用组件 size，而不是全局压缩字体和 line-height。

### 反馈与浮层

Message 用于短结果；Notification 用于有标题、解释或动作的持续通知；Alert 位于关联内容附近显示当前风险或说明。Message / Notification 的语义色主要用于图标，正文保持正常文字；Alert 使用语义浅底。

Tooltip 放简短补充信息；有按钮、链接或富内容时选择 Popover。关键错误、权限提示、操作名称不能只藏在 hover Tooltip。Modal 用于阻断并完成当前确认或短表单；Drawer 用于保留底层页面上下文的详情或较长编辑。两者标题 16px/500、标题区域高 48px；Modal 默认 520px，Drawer 默认 250px。业务需要更宽编辑 Drawer 时明确设置 width，并记录为页面配置，不改变此处官方默认。使用组件现有焦点、键盘与 Portal 能力，实际验证 Esc、焦点恢复和叠层。

### 等待与空状态

Progress 表达可量化进度；无法测量时采用 loading / Skeleton，不伪造百分比。默认线条厚 4px，圆环 64px；100% 后根据真实任务结果回显成功或错误。Skeleton 的结构应对应即将出现的标题、图片或正文。Empty 只表示请求成功且结果为空，文案区分“尚无数据”与“筛选无结果”，后者提供清除筛选；网络失败显示恢复入口，不能套用 Empty。

## Do's and Don'ts

下表是用于约束生成器的规则；涉及布局策略的数值为本分析建议，组件默认值以 YAML 与源码为准。

| Do：必须执行 | Don't：禁止生成 |
| --- | --- |
| 每个独立操作组只放一个实底 primary；删除放 danger 状态。 | 让查询、重置、导出、删除全部使用蓝色实底 primary。 |
| 同一筛选条统一 size，查询与重置紧邻，条件和结果置于同一内容列。 | 把表单拆成无对齐关系的多张卡片或将重置放到另一侧角落。 |
| 使用 Form.Item 的 field、label、rules；错误显示在字段附近。 | 只靠 placeholder 命名字段，或失败后只弹 Message 而不标错字段。 |
| 根据 default / hover / active / disabled / focus 选取已有状态令牌。 | 用全局 opacity 模拟全部禁用，或让选中态与悬浮态始终完全相同。 |
| 状态用图标或文案辅助颜色，必要业务数据使用一级或二级文字。 | 用灰色禁用文字展示必须阅读的价格、金额、权限与错误原因。 |
| 操作图标提供名称；长文本截断时保留可访问的完整文本入口。 | 在必须点击的入口只放没有标签的图标，或截断唯一标识且无恢复入口。 |
| 请求成功但无数据才显示 Empty；请求失败提供重试。 | 加载、空结果、网络失败全部显示同一种空插图。 |
| Table 明确主标识、状态、关键数值与操作列；数值靠右，文字靠左。 | 为同一列每行使用不同对齐、单位或小数位，金额省略币种。 |
| 同一系列跨图表保留颜色、名称与单位。 | 每次数据排序后根据当前位置重新分配系列颜色。 |
| 保留默认 2px 控件圆角和 4px 浮层圆角；扩展必须先登记。 | 把后台所有输入、卡片和弹层统一替换成大圆角胶囊。 |
| 用 theme CSS 变量、公开 Less token 和 props 进行改造。 | 依赖私有 DOM 层级覆盖全站状态，或把所有元素强制写成浅色 hex。 |
| 手机先折叠导航，再整理操作条和查询，最后收拢网格。 | 直接缩小桌面页面到手机，或用 body overflow:hidden 掩盖横向溢出。 |
| 弹窗成功后才关闭并更新对应数据；失败保留用户输入。 | 点击提交立即关窗，随后用成功提示掩盖未完成请求。 |

## Responsive Behavior

断点来自当前 [`responsiveObserve.ts`](https://github.com/arco-design/arco-design/blob/c2b050d9c7ce94bebba94f616a0721344231caac/components/_util/responsiveObserve.ts)；设备类别和折叠规则为本分析生成策略，不是组件库自动替页面完成的布局。

| 断点 | 实际媒体查询范围 | 本分析设备语境 |
| --- | --- | --- |
| xs | max-width: 575px | 手机；以单列和 Drawer 导航为主。 |
| sm | min-width: 576px | 576–767px 为较窄平板区间。 |
| md | min-width: 768px | 768–991px 为较宽平板区间。 |
| lg | min-width: 992px | 992–1199px 为桌面起点。 |
| xl | min-width: 1200px | 1200–1599px 桌面。 |
| xxl | min-width: 1600px | 1600–1999px 宽桌面。 |
| xxxl | min-width: 2000px | ≥2000px 超宽桌面。 |

sm 及以上查询会同时匹配；表中区间是说明用途的互斥分段，不应把 min-width 断点写成排他布尔状态。Sider 的 breakpoint 是可配置响应式能力；为本策略显式选择 `lg`，并控制 collapsed，不假设组件默认已经启用 breakpoint。[官方响应式 Skill](https://github.com/arco-design/arco-design-skill/blob/47b174eb9c5866db3d1de20bd4a4ce5f2541eb8a/skills/arco-design/references/patterns/responsive-design.md)

从宽到窄按以下顺序执行：

1. **导航**：≥992px 展示展开 Sider；576–991px 折叠到明确设置的 48px 图标栏，保留 Tooltip 和键盘名称；≤575px 移除常驻 Sider，通过带“打开导航”名称的按钮打开 Drawer。选中项始终与 URL 对应，折叠不改变当前选中页面。
2. **标题与操作条**：平板先将导出、批量次要操作收进 Dropdown；手机标题、说明和按钮分行，保留主要动作，按钮组可换行。Breadcrumb 手机保留当前与上一级路径，更多层级有可用入口，不溢出页面。
3. **筛选与表单**：≥992px 普通筛选条件最多三列；768–991px 两列；<768px 单列。短查询可以保留一行，但不得让按钮挤到输入区。手机改成垂直标签；不是仅缩短 labelCol 而保持窄输入。日期范围、前后附加控件与错误文字也必须纳入限宽。
4. **多列内容**：普通工作模块用 `xs=24, sm=12, md=12, lg=8`，形成 3→2→1 列；四张紧凑统计卡可用 `xs=24, sm=12, md=12, lg=6`，形成 4→2→1。长表单与主数据表始终占 24 栏，不为了对称强拆成卡片。
5. **表格**：先移出低优先级列，优先级为附加说明→次要时间与来源→次要统计；主标识、关键状态和行操作仍可访问。需要隐藏的字段放进详情展开。剩余列仍超宽时用 Table 的横向 scroll，在局部容器滚动，不让整个页面横向滚动。对手机任务确实需要卡片摘要时，保留筛选、排序、分页和完整详情入口，不直接丢弃字段。
6. **分页与浮层**：平板减少页码按钮，手机用 simple 分页并保留总量说明。Modal 窄屏最大宽为 `calc(100vw - 24px)`；Drawer 编辑区可设为可视区宽度，采用顶部标题、内部滚动与可见提交区域。Popover / Tooltip 限制可用宽度，保持锚点与关闭入口，不能超出屏幕。

触屏建议是本分析的交互增强：图标入口的外部可点击区域至少 40×40px；14px 的 Checkbox / Radio 标记保留其默认视觉尺寸，通过标签和容器扩大点击区。主要触屏提交可设置外部 40px 高度；这属于页面策略，不能把默认 large=36px 改写成 40px。该数值不等于本文件已经完成某项可访问性认证。

验收宽度至少包含 390px、575/576px、767/768px、991/992px、1200px、1600px 和 2000px；跨断点观察导航、表单、局部表格滚动与弹层，不仅测一次桌面截图。

## Iteration Guide

1. 先读 `provenance`，核对项目实际 Arco 版本与主题覆盖；本分析默认主题与项目主题不同，应建立显式覆盖记录，保留本文件官方基线。
2. 先确定任务、数据状态和主要动作，建立 PageHeader→查询/操作→Table/Form→反馈结构，再应用组件令牌。
3. 修改一个组件族时同时审查所有状态；变更主色时覆盖完整色板和语义状态，避免只换 default。
4. 新增语义角色时先写入 YAML，再引用。每项新增数据写明 source 或 origin；不得填写不存在的令牌路径。
5. 深色先应用 `themes.dark.colorOverrides`，随后应用 `componentOverrides`；先合并属性，再递归解析引用。组件特定暗色样式优先于通用颜色重绑定。尺寸补丁仅合并 overrideOnly 所列属性；组件的显式 lineHeight / titleLineHeight 优先于 typography 的行高。
6. 用真实内容检查长名称、多位金额、中文错误、多选内容、空结果、请求失败和加载；再检查窄屏与键盘导航。
7. 编辑后执行下列标准解析校验；校验通过仅证明文档结构与引用有效，不能替代源码对照、浏览器交互或可访问性检测。

可重复运行的校验器，依赖 Python 3 与标准 PyYAML 解析库；不会修改文件，不需要在项目中新增依赖。它检查重复 YAML 键、八项必需字段、全文令牌引用、引用环、hex 颜色、章节顺序、组件覆盖与外来设计语言字符串。形式参考来源允许出现参考文件名，但不允许被带入样式规则。

```python
from pathlib import Path
import json
import re
import yaml

path = Path("Arco-Design-DESIGN.md")
text = path.read_text(encoding="utf-8")
parts = text.split("---", 2)
assert parts[0] == "" and len(parts) == 3, "缺少 YAML Frontmatter"

class UniqueLoader(yaml.SafeLoader):
    pass

def unique_mapping(loader, node, deep=False):
    result = {}
    for key_node, value_node in node.value:
        key = loader.construct_object(key_node, deep=deep)
        assert key not in result, f"重复 YAML 键: {key}"
        result[key] = loader.construct_object(value_node, deep=deep)
    return result

UniqueLoader.add_constructor(
    yaml.resolver.BaseResolver.DEFAULT_MAPPING_TAG, unique_mapping
)
data = yaml.load(parts[1], Loader=UniqueLoader)
required = "version name description colors typography rounded spacing components".split()
assert all(key in data for key in required), "缺少必需字段"
assert all(isinstance(data[k], str) and data[k] for k in required[:3])
assert all(isinstance(data[k], dict) and data[k] for k in required[3:])

def leaves(obj, prefix=""):
    for key, value in obj.items():
        p = f"{prefix}.{key}" if prefix else str(key)
        if isinstance(value, dict):
            yield from leaves(value, p)
        else:
            yield p, value

def lookup(token):
    obj = data
    for key in token.split("."):
        assert isinstance(obj, dict) and key in obj, f"不存在的引用: {token}"
        obj = obj[key]
    return obj

pattern = re.compile(r"\{([a-zA-Z][\w-]*(?:\.[\w-]+)+)\}")
references = pattern.findall(text)
for token in references:
    assert token.split(".")[0] in {"colors", "typography", "rounded", "components"}
    lookup(token)

def inspect_cycles(token, chain=()):
    assert token not in chain, f"引用环: {chain + (token,)}"
    value = lookup(token)
    for target in pattern.findall(str(value)):
        inspect_cycles(target, chain + (token,))

for token in set(references):
    inspect_cycles(token)
for name, value in leaves(data["colors"]):
    assert isinstance(value, str) and re.fullmatch(r"#[0-9A-Fa-f]{6}(?:[0-9A-Fa-f]{2})?", value), name

expected = [
    "Overview", "Colors", "Typography", "Layout", "Elevation & Depth",
    "Shapes", "Motion", "Components", "Do's and Don'ts", "Responsive Behavior",
    "Iteration Guide", "Known Gaps", "Reference Sources"
]
assert re.findall(r"^## (.+)$", parts[2], re.M) == expected, "章节缺失或顺序错误"
for key, component in data["components"].items():
    assert all(p in component for p in [
        "backgroundColor", "textColor", "borderColor", "typography", "rounded",
        "padding", "height", "width"
    ]), key
    assert "{components." + key + "}" in parts[2], f"正文未覆盖组件: {key}"
for style in data["typography"].values():
    assert all(k in style for k in [
        "fontFamily", "fontSize", "fontWeight", "lineHeight", "letterSpacing"
    ])
# 字符串拆开写，避免校验器的禁止词列表被正文扫描命中。
foreign = ["Go" + "ogle", "Mat" + "erial", "Ant " + "Design", "ant" + "d",
           "Ra" + "dix", "Cha" + "kra", "Sho" + "hne", "Sty" + "rene",
           "Cop" + "ernicus", "#" + "cc785c", "#" + "faf9f5"]
for word in foreign:
    assert not re.search(r"(?<![\w-])" + re.escape(word) + r"(?![\w-])", text, re.I), word
print(json.dumps({
    "lines": len(text.splitlines()),
    "colors": len(list(leaves(data["colors"]))),
    "typography": len(data["typography"]), "rounded": len(data["rounded"]),
    "spacing": len(data["spacing"]), "components": len(data["components"]),
    "componentProperties": len(list(leaves(data["components"]))),
    "references": len(references), "uniqueReferences": len(set(references)),
    "result": "PASS: YAML / required fields / references / colors / sections / foreign rules"
}, ensure_ascii=False, indent=2))
```
