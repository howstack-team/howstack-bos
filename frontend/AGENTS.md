# 皓量云擎云业务运营系统前端开发规范

## 适用范围

本文件适用于 `frontend/` 及其所有子目录，并继承仓库根目录 `AGENTS.md`。子目录若存在更具体的 `AGENTS.md`，继续叠加执行。

## 技术栈与应用边界

- 三个应用使用 TypeScript 和 Vite；运营后台使用 React 18 与 Arco Design React，会员控制台使用 React 19 与 Arco Design React，在线安装器使用 React 19 与 Arco Design React。
- `admin/` 是运营后台，`console/` 是会员控制台，`install/` 是在线安装器；三者必须保持独立构建和独立路由。
- 后台页面入口为 `/admin`（安装时可自定义首级路径），会员控制台入口为 `/console`；Vite base、React Router basename、图标和静态资源路径必须一致，不增加 `/app` 前缀。API 继续使用 `/api/admin/v1`、`/api/console/v1`，不随页面入口变更。
- 三个应用的生产构建统一输出到 `backend/public/` 的受控目录，随后端发行包交付；客户服务器不得依赖 Node.js 或现场构建。
- 禁止从一个应用直接引用另一个应用的 `src/`；需要复用的 API、类型、Schema 渲染器和通用组件应进入 `packages/`，并通过明确的包入口导入。
- 共享包必须有清晰职责和稳定公开 API，禁止把具体业务页面或应用私有状态迁入共享层。
- 禁止直接修改 `node_modules/`、`dist/` 及其他构建生成内容。

## TypeScript 与 React 规范

- 禁止使用 `any`；外部数据先定义类型，并在 API、存储、消息和插件边界完成运行时校验。
- 组件保持单一职责；业务请求、状态编排和展示逻辑应合理拆分，避免超大页面组件。
- Hooks 必须遵循调用规则，副作用需明确依赖和清理逻辑，不在渲染阶段执行写操作。
- API 地址、路由名称、权限标识、查询键和缓存策略集中管理，不在页面组件中散落硬编码。
- 页面必须处理加载、空数据、错误、无权限和提交中状态；异步操作应防止重复提交并提供清晰反馈。
- 用户可见文案默认使用中文；协议字段、产品标识和第三方专有名词按实际契约保留英文。

## 复用、工具与组件规范

- 多处重复且语义稳定的操作可以封装为工具函数、工具模块、Hook 或组件，避免复制粘贴；封装前应确认职责、输入输出、状态和副作用边界清晰，不能为单次使用或表面相似的代码过早抽象。
- 日期、金额、文本、枚举映射、脱敏、校验和序列化等无 UI、无状态的逻辑优先封装为纯工具函数；TypeScript 中优先使用具名函数和模块，仅在确需封装实例状态或明确协议时使用工具类。
- 包含 React 状态、副作用、请求编排或浏览器生命周期的可复用操作应封装为自定义 Hook，不得伪装成普通工具函数，也不得绕过 Hooks 调用规则。
- 可复用的视觉结构和交互行为应封装为组件；组件通过类型明确的 Props、事件和受控状态对外通信，不得隐藏依赖于页面全局变量、路由对象或未声明 Context 的行为。
- 业务规则、权限决策和完整业务流程不得塞入万能工具或通用组件。页面负责用例编排，领域相关逻辑放在对应业务模块；公共组件只承载稳定、可组合的展示与交互能力。
- 仅在单个应用内复用的代码放入该应用的 `src/` 对应目录；跨 `admin`、`console`、`install` 复用且契约稳定的工具、Hook、类型和组件才进入 `frontend/packages/`，禁止跨应用直接引用彼此源码。
- 不得创建职责含糊的 `utils.ts`、`common.ts` 或超大 `CommonComponent`；文件、导出名称和目录应表达具体用途，并保持可按需导入，避免循环依赖和无边界公共 API。
- 工具、Hook 和组件应覆盖空值、异常、加载、禁用及边界输入；导出的公共能力必须补充准确类型和 TSDoc，重要纯逻辑应有单元测试，交互组件应按风险补充组件或浏览器测试。
- 抽取或修改公共能力前必须搜索全部调用方，同步更新全部受影响调用方；当前未上线的内部 API 使用最新契约，不保留旧字段或旧接口兜底。正式发布后再按消费方安排兼容与迁移；不得为了消除少量重复而引入更难理解的配置层或条件分支。

## 注释与 TSDoc 规范

- 对导出的组件、Hooks、函数、类型、接口、类、常量和共享包公共 API 尽量编写 TSDoc，说明用途、参数、返回值、状态变化、副作用、错误行为和使用约束。
- TSDoc 使用标准的 `/** ... */` 形式；根据实际需要准确使用 `@param`、`@returns`、`@throws`、`@remarks`、`@example`、`@typeParam`、`@deprecated` 和 `@see` 等标签。
- 组件 Props、Schema、API DTO、插件消息和复杂联合类型中的字段，如果名称不足以表达业务语义、单位、取值范围、可空条件或兼容规则，应逐项补充文档注释。
- TSDoc 不能替代 TypeScript 类型；应优先提供精确类型和判别联合，文档负责补充类型系统无法表达的业务语义、运行时校验要求与调用约定。
- Hooks 依赖、缓存失效、竞态处理、权限判断、跨窗口通信和兼容性分支等不直观逻辑，应使用行内注释解释设计原因，不要逐行复述代码或保留大段已注释掉的废弃实现。
- 注释必须与实现同步更新；公共 API 行为变更时同步更新 TSDoc、示例和弃用说明，过期或误导性注释必须修正或删除。

## Arco Design 组件与视觉规范

三个应用统一使用 Arco Design React；运营后台的布局、权限与表格专项规则见 `frontend/admin/AGENTS.md`，在线安装流程规则见 `frontend/install/AGENTS.md`。

- 页面优先使用 Arco 的 `Table`、`Form`、`Descriptions`、`Card`、`Modal`、`Drawer` 等原生组件及项目已有组件，不引入 Ant Design、ProComponents，也不重复实现已有基础组件。
- 表单中的整数字段优先使用 Arco `InputNumber mode="button"` 左右加减按钮模式，明确 `precision={0}`，按业务设置 `min/max/step` 并保留原有取值范围、空值和提交类型。窄表格或其他确实不适合按钮模式的场景可按实际布局选择；不通过私有样式模拟按钮。金额、比例等允许小数的字段保留原有精度及单位，不套用整数规则；手机号、工号、邮编、编号和标识等文本字段不得因为包含数字改用数字输入框，避免丢失前导零或符号。参见 [数字输入框](https://arco.design/react/components/input-number)。
- 表单字段有明确单位时，使用 Arco `Input` / `InputNumber` 的公开 `suffix` 参数在输入框内展示单位（如分钟、秒、小时、MiB、GiB、MHz、Mbps、MB/s、IOPS、%、px）；`label` 只保留字段名称，不写成“内存（MiB）”或“退款申请窗口（小时）”，不通过 placeholder 或独立文本代替后缀。金额继续使用统一 `PriceInput` 的 `¥` 前缀及“元 / GiB”等单位后缀。动态插件字段的单位由声明中的 `unit` 提供。单位的解释、范围和换算说明仍可放在 `tooltip` / `extra`，后缀只用于展示，不进入输入值，也不改变数值单位、精度、范围或 API 提交类型。参见 [输入框前后缀](https://arco.design/react/components/input#%E5%89%8D%E5%90%8E%E7%BC%80)。
- 表单的 `Input`、`Input.Password`、`Input.TextArea`、`InputNumber` 及可搜索选择框尽量填写有业务含义的 `placeholder`，使用简短的填写/选择提示或合法示例；选填字段说明可空含义，编辑密码说明留空保持原值。占位文字不能替代字段标签、默认值或校验；不得将密码、密钥等真实敏感内容放入占位提示。动态插件表单优先使用声明中的占位文字，缺失时根据字段名称和类型补充。
- 字段说明优先使用 Arco `Form.Item` 的 `tooltip` 或 `extra`：格式、单位解释及辅助说明放在 `tooltip`，必须持续可见的取值范围、计费规则、留空语义和操作影响放在 `extra`。标签保持简短，不把长说明塞进标签或占位文字；校验失败仍由字段 `rules` 展示准确错误。已有说明保留真实业务含义，不将后端错误改成静态提示。参见 [表单](https://arco.design/react/components/form)。
- 表单容器按任务复杂度、是否需要参照主页面以及路由状态需求选择，遵循下方“表单容器决策规则”；不要把所有表单统一改为双列 Modal，也不要通过压缩字体、隐藏字段、增加 Tab 或内部滚动将长表单塞入 Modal。
- 排版与容器选择分别判断：短表单默认窄单列；中等表单综合字段长度、控件宽度与业务关联决定是否并排，描述、长文本和多选等宽字段独占整行。窄屏并排字段自然改为单列，不按设备类型强制更换容器。Modal 不设置表单内部 `max-height/overflow-y: auto`；Drawer 只由原生内容区滚动；独立页面随主内容滚动。文本编辑器自身的编辑区滚动不属于容器滚动。
- 所有 Modal 和 Drawer 必须支持点击遮罩层关闭，显式设置 `maskClosable`（静态 `Modal.confirm/info/success/warning/error` 使用 `maskClosable: true`），并通过 `onCancel` 完成关闭状态更新及必要的清理；不得将遮罩关闭绑定到提交、审核或删除等确认操作。各应用根部的 `ConfigProvider` 为 Modal、Drawer 设置 `maskClosable: true` 默认值，不使用保存中状态拦截遮罩关闭。窄屏抽屉应保留可点击的遮罩区域，最大宽度使用 `calc(100vw - 24px)`。关闭界面不等于取消已提交的业务请求，仍需保留防重复提交及结果反馈。
- 所有 UI 开关统一使用 Arco `Switch type="round"`。各应用根部的 `ConfigProvider` 设置 `componentConfig={{ Switch: { type: 'round' } }}` 默认值，业务组件也显式声明 `type="round"`；不使用 CSS 模拟圆形开关。此规则不适用于路由组件 `Switch`。
- 状态字段只有“启用 / 禁用”时，表单使用带对应文字的 `round` 开关，并在回填、提交时按接口契约转换整数状态；不能把布尔值直接传给整数状态接口。
- React 19 应用入口加载 Arco 官方 React 19 adapter；所有应用加载本地 Arco CSS 和中文语言包，遵循实际安装版本的公开 API 和类型定义。
- 全局主题色固定为 `#165DFF`，矩形组件圆角固定为 `2px`，通过官方 CSS 变量和应用根部 `ConfigProvider` 配置；不在页面或组件内另行硬编码矩形圆角。业务组件使用 Design Token 或项目 CSS 变量；头像和圆形图标按钮保留原生形状，开关通过 `type="round"` 设置原生类型。
- Arco 原生样式、交互状态和内部结构保持默认，不依赖 `.arco-*` 私有 DOM、`!important` 或私有 CSS 变量重写组件。需要调整行为或外观时，优先使用公开 Props、插槽和 Design Token。
- 自定义样式不增加 `box-shadow`、`text-shadow` 或 `filter: drop-shadow()`；层级使用实色背景、边框、间距和排版表达。原生浮层样式保留。
- 不使用位移、缩放、悬停抬升、CSS `float`、拟态玻璃、`backdrop-filter`、背景模糊或渐变效果；页面布局使用 Flex、Grid 或正常文档流。
- 所有业务图表统一使用 VChart；单个统计数值使用 Arco `Statistic`。不引入 Ant Design Charts、ECharts、Chart.js、Recharts，也不手写 Canvas、SVG 或用静态图片模拟图表。
- 页面标题只由业务页面提供；Layout 负责导航和内容容器，不重复渲染标题或面包屑。
- 表格和列表设置稳定的列宽、溢出和空状态策略；长内容列设置合理宽度及 `ellipsis: true`，操作区保持可访问和可操作。
- 表格按业务需要为适合比较的列增加排序、为适合分类的列增加筛选，遵循下方“表格列排序与筛选规则”；不得为了统一外观给所有列机械添加入口。
- 表格中的分类、类型和业务状态遵循下方“表格分类与状态展示规则”：无好坏、风险或优先级之分的普通分类保持纯文本；每个表格原则上只选一列主要流程状态使用带文字的 `Badge`，不把所有字段机械包装成标签或徽标。
- 表格的查询、搜索及筛选表单以 Arco `Form layout="inline"` 和 `Form.Item` 组织，遵循下方“表格查询表单规则”；不使用 `Space` 或普通容器模拟查询表单，查询区与表格工具栏分行。
- 表格上方查询区和工具栏的操作按钮统一增加语义明确的 Arco 图标，包括查询、重置、新增、刷新、批量操作和辅助工具。按钮和 `Link` 优先使用公开 `icon` 属性并保留文字；纯图标工具必须提供可访问名称。表格内部操作列使用文字 `Link`，行内编辑、详情、删除及“更多”菜单项不添加图标；保留原有权限、禁用、加载及确认逻辑，操作列保持单行。
- 表格工具栏全站统一遵循“左批量，右全局；主操作可右上，辅助工具必右上”。左侧放选中数量及针对选中记录的批量删除、批量启用/禁用、导出所选等操作；右上方放作用于整个列表的新增、导入、导出全部等全局操作，以及刷新、列设置、密度、全屏等辅助工具。本项目新增/创建等主操作统一放在右上方，主操作组与辅助工具组合理分隔，同类入口不得因页面不同而左右切换。没有批量操作时不占用左侧空间，也不将右侧工具移到左侧；窄屏换行仍保留分组及顺序。查询/重置按钮跟随 inline 查询表单，行内操作保留在对应记录的操作列，不混入工具栏。
- 至少验证桌面与 `390px` 页面，检查导航、表单、表格、卡片、弹窗和抽屉的重排、可操作性、横向溢出、滚动归属及控制台错误。

## 表格分类与状态展示规则

- **普通分类保持纯文本**：订单类型、产品类别、认证类型、客户类别、渠道类型等没有好坏之分的分类保持原来的纯文本，不加彩色 Tag。优先级、风险等级等确有突出语义的字段才按需要少量使用 Tag，不因选项有限或字段可筛选就强制加标签。名称、编号、金额、时间和长描述保持普通文本。
- **徽标集中在主要状态列**：每个表格尽量只有一列使用 `<Badge status="..." text="中文状态" />`，选择最重要的业务生命周期或处理结果；其他辅助状态保持中文纯文本。例如订单列表的“订单状态”使用徽标，“支付状态”使用文字；充值、审核、安装任务等表格选择其主状态列。使用原生圆点加文字，不用数字计数徽标表示流程状态，不只展示无文字圆点。
- **颜色按语义映射**：成功/完成使用 `success`，实际执行中使用 `processing`，需要关注或待处理使用 `warning`，失败/异常使用 `error`，未开始、取消、关闭等中性状态使用 `default`。待支付、待审核等状态按实际业务区分中性等待与需要关注，不把所有“待处理”显示为正在执行，也不把取消一律显示为失败。
- **文案与颜色保持一致**：同一枚举在不同列表中保持相同中文文案；确需使用 Tag 的语义字段保持一致配色，不用成功/失败颜色装饰普通分类。标签与徽标采用原生尺寸，不自定义放大，不重写组件私有样式；识别必须同时依靠文字，不能仅靠颜色。
- **启用 / 禁用单独沿用原样式**：运营后台“启用 / 禁用”继续使用 `EnabledStatus` 的图标加文字，不改为 Tag 或 Badge；本节的分类标签和流程状态徽标规则不适用于此类状态。账号绑定等已有专项约定的状态也继续使用既定图标文字样式。
- **枚举与显示共用映射**：文案、颜色和表头/查询区筛选选项集中维护，原始值遵循接口契约，不修改提交参数。未知枚举显示“未知状态”或经确认可展示的原始值，并使用中性样式；不能误显示为成功、启用或禁用。空值仍遵循 `-` 占位规则，`0` 和 `false` 按业务契约判断，不能当作空值。
- **控制信息密度**：仅在有分类或状态识别价值时使用 Tag/Badge，避免同一单元格叠加重复标签、徽标和状态图标。多分类字段按列宽显示，确需收纳时显示剩余数量并提供完整内容入口，不撑高每行或挤压操作列。状态样式不替代排序、筛选、详情及操作能力。

## 表格列排序与筛选规则

- **按字段用途选择**：时间、金额、数量、容量、优先级、业务排序值等具有明确比较意义且用户需要比较的列，通常应提供升序/降序排序；状态、类型、启用状态等选项明确且数量有限的列，通常应提供列筛选。地域、部门等列只有在选项规模可控、来源完整且有实际筛选需求时提供筛选。一个字段可同时支持排序和筛选，两者分别判断。
- **避免无意义入口**：操作、头像、图片、长描述、敏感信息及无比较意义的标识列默认不加排序或筛选。名称是否排序取决于实际查找需求及约定的文字排序规则；订单号、手机号、工号等不得按数字强行比较。不将所有字段都变成列筛选，也不使用当前页出现的值冒充完整筛选选项。
- **使用原生能力**：遵循已安装 Arco 的公开 API，通过列的 `sorter`、`sortOrder`、`sortDirections`、`filters`、`filteredValue`、`onFilter` 及表格 `onChange` 实现；使用原生排序/筛选图标与交互，不自制表头按钮或覆盖组件私有样式。选项使用可理解的中文名称，实际值保持接口枚举，明确单选/多选及清空行为。参见 [Arco 表格排序和筛选](https://arco.design/react/components/table#%E6%8E%92%E5%BA%8F%E5%92%8C%E7%AD%9B%E9%80%89)。
- **区分数据范围**：服务端分页列表必须由后端对完整授权数据集先筛选、排序，再分页，并返回一致的总数；列排序使用 `sorter: true` 配合 `onChange` 发送已约定参数，不使用比较函数只排序当前页，也不使用 `onFilter` 只过滤当前页。只有明确已取得完整数据集的列表才能在客户端排序/筛选。接口尚未支持时应补齐契约和后端实现后开放入口，不展示无实际效果的功能。
- **保持结果稳定**：前后端约定允许排序的业务字段、方向、默认顺序、空值位置及文字/日期/数值的比较规则；后端将允许字段映射到固定列，不直接使用客户端传入的 SQL 列名。存在相同排序值时追加稳定且唯一的排序键，避免跨页重复或遗漏；默认单列排序，确有业务需要时才使用多列排序并明确优先级。
- **与查询表单共用状态**：列筛选与已应用查询条件统一管理；同一字段在查询区和表头同时提供入口时必须同步显示和请求值，不维护两套互相冲突的条件。不同字段按 AND 组合，同一字段多选按 OR 匹配。列筛选提交或清空立即生效，修改排序/筛选时页码归 1，保留其他已应用条件和每页条数；全局重置清空查询及列筛选并恢复约定的默认排序，单列清空不影响其他字段。
- **状态与验收**：已应用列筛选、排序字段和方向同步 URL，遵守查询表单的白名单、恢复和敏感信息规则；受控表头状态与请求、结果保持一致，刷新、详情返回和前进/后退可恢复。请求中显示加载状态并隔离旧响应。验证升序/降序/取消排序、筛选/清空/组合条件、分页总数、跨页顺序、空值与相同值、状态 `0` 及返回恢复；不能将当前页变化当作完整数据集验证。

## 表格查询表单规则

**目标是快速过滤数据：字段少而精、布局轻、交互快、状态可保留。**

### 位置与布局

- 查询区放在表格上方独立一行，只负责筛选数据；下一行是表格工具栏，遵循“左批量、右全局”。新增、删除、导入、刷新、列设置等操作不得混入查询表单；查询、重置及展开/高级筛选放在查询区行尾。
- 少字段以 `inline` 为主；字段数量是经验值，综合控件长度、实际可用宽度和使用频率判断，不为凑数量添加条件，也不强迫长字段塞进一行。

| 条件规模 | 默认布局 | 查询区操作 |
| --- | --- | --- |
| 1–4 个简单字段 | inline 平铺，宽度不足自然换行 | 查询、重置 |
| 5–8 个字段 | 常显 3–4 个高频字段，其余折叠 | 查询、重置、展开/收起 |
| 超过 8 个字段或复杂条件 | 常显 2–3 个高频字段，其余使用高级筛选 Drawer；少量简单高级条件可用 Modal | 查询、重置、高级筛选 |
| 窄屏 | 保留一个高频查询字段、查询及筛选入口，其余条件进入筛选 Drawer | 查询、筛选；重置可在筛选区提供 |

- 展开/收起或关闭高级筛选不得擅自清空已应用条件；展示已应用筛选数量或摘要，避免隐藏条件造成误解。Drawer、Modal 仍遵守统一遮罩关闭规则；筛选区取消不提交未应用修改。

### 字段选择

- 查询条件按业务字段独立提供（如昵称、手机号、邮箱、订单号、认证主体），多个非空条件使用 AND 组合；不得仅用一个通用“关键词”输入代替多个业务字段，也不得只更换标签却仍在后端跨字段 OR 匹配。优先选择高频且区分度高的字段：名称/ID 用 `Input`，状态/类型用 `Select`，时间用 `DatePicker.RangePicker`，负责人/部门用 `Select` / `TreeSelect`，金额/数量范围用数字输入框组合。金额、整数和单位遵循既有组件规范。
- 标签简短，placeholder 有业务含义，适用控件允许清空；不把录入表单的全部字段照搬为筛选项，不设置无业务依据的默认筛选或必填规则。范围条件只做必要的合法性校验，如起止时间、最小值与最大值关系。

### 查询与状态

- 显式查询使用主按钮，重置使用次按钮，均带语义图标；输入框回车等同查询，统一处理查询提交，避免按键回调和表单提交重复请求。
- 应用新条件或重置时页码归 1；重置清空条件（确有业务默认值时恢复默认值）并立即重新获取/过滤数据，不能只清空控件。单纯刷新保留已应用条件及当前分页。
- 实时搜索使用约 300ms 防抖；回车/显式查询立即应用最新输入，并取消待执行防抖。切换每页条数时页码归 1，后端分页按新参数请求。
- 区分正在填写的条件和已应用条件。查询时展示 loading、防止重复提交，较晚返回的旧请求不能覆盖新条件的结果；错误时保留条件并提供重试。
- 已应用条件、页码及每页条数同步到 URL query；刷新、分享、直接访问及浏览器前进/后退均可恢复，详情或编辑页返回列表时保留状态。URL 参数按允许字段、枚举、范围和默认值解析，不覆盖已有工作台 `tab`、编辑入口等参数；禁止放入密码、密钥、令牌等敏感内容。
- 提交查询建立可返回的 URL 状态，输入中间值不反复新增历史记录；同步 URL 与请求使用同一份已应用条件，避免界面、地址和数据不一致。URL 保留筛选状态不等于持久化未提交表单草稿。
- 验收覆盖按钮/回车查询、清空重置、分页归 1、刷新保留、详情返回、分享/直接访问、前进/后退、失败重试、请求竞态，以及展开和窄屏筛选无横向溢出。

## 表单容器决策规则

**轻量、确认型、快速完成 → Modal；中等复杂、需参照背景列表或详情 → Drawer；复杂、长表单、多步骤或需要 URL 状态 → 独立页面。**

| 容器 | 适用任务 | 当前项目示例 |
| --- | --- | --- |
| Modal | 少量简单字段，完成后立即回到原上下文；删除、改名、状态确认 | 分类、部门、角色基本信息、工单类型、分组/等级、简单资源 |
| Drawer | 中等 CRUD、补充资料或配置，需要参照列表/详情，允许原生内容区滚动 | 会员/系统用户、镜像/规格/网络参数、供应商连接配置、交付规则 |
| 独立页面 | 长时间编辑、多区配置、复杂价格、动态表格、富文本或多步骤；需要直接访问、刷新回填、分享、后退或草稿 | 内容正文、销售方案、存储类型配置、供应商资源对应、系统设置、安装向导 |

- 决策顺序：先判断复杂/长/多步及 URL、刷新、后退、草稿需求；满足时使用页面。其次判断中等复杂且需要参照主页面，使用 Drawer。最后判断少量字段、快速确认或补充，使用 Modal。仍不明确时按真实渲染高度与操作路径判断，优先 Drawer 或页面，避免硬塞 Modal。
- 字段数只是经验值：约 1–5 个简单字段优先 Modal，约 6–20 个优先评估 Drawer，20+ 个或分步、动态表格、富文本优先页面；不作为硬阈值。六个短字段的角色表单仍可使用 Modal，少量字段的正文编辑也应使用页面。
- Drawer 的背景用于参照，遮罩下主页面不能直接交互。若任务需要同时操作两侧内容，使用页面内的并排区域，不能仅靠取消遮罩实现。背景关闭必须遵循本项目统一遮罩规范。
- 禁止 Modal 套 Modal、叠加多层 Drawer，以及在 Drawer 内建设复杂多步表单。确认可在当前容器内切换确认状态，详情切换先关闭原浮层；复杂局部任务转为页面。简单快速编辑可提供“高级编辑”页面入口，但不能强迫改两个字段就跳整页。
- 移动端保留已有容器语义，只适配可用宽高和键盘空间；不强制将所有 Modal 换成底部弹层或全屏 Drawer。本项目 Drawer 保留至少 24px 可点击遮罩区域，不机械照搬全屏方案。轻量 Modal 在实际内容放不下时可由 `FormDialog` 转为 Drawer，并保留输入及校验。
- 独立编辑页面可复用现有业务路径加受控查询参数，如 `?edit=记录编号`、`?mapping=供应商编号`；无需为同一资源重复建设菜单。进入/退出保留列表筛选、分页和工作台 Tab；支持直接访问、刷新重新读取已保存记录、浏览器后退及权限/不存在/读取失败状态。
- 编辑入口的 URL 参数只保存任务与记录标识，不保存密码、密钥或表单正文；列表的已应用筛选及分页按“表格查询表单规则”保存。刷新回填已保存数据不等于保留未提交草稿；确需草稿时单独定义保存、恢复、过期、权限及敏感字段规则，不能为了换容器擅自将表单写入浏览器存储。
- 容器迁移必须保持字段、校验、金额单位/精度、空值和提交契约；核对保存、取消、遮罩关闭、失败重试和防重复提交。页面还要检查直接访问、刷新、返回、分享链接与无权限状态。

## 插件前端边界

- 插件前端必须以预构建、版本化资源交付，客户服务器不执行 `npm install` 或运行时编译。
- 插件分类、配置声明、固定动作和 SDK 边界见 [业务插件体系优化方案](../docs/architecture/business-plugin-optimization.md)。配置表单由宿主根据受限 Schema 渲染，不执行自定义字段脚本；插件设置、渠道连接和业务绑定分别管理，密钥只通过专用输入提交，不回显。
- 产品类型必须拥有与其业务语义匹配的专属管理页面和购买配置器。云服务器的地域、可用区、线路、规格、镜像、系统盘、数据盘、带宽、IP、防护和初始化信息等关键结构、联动与价格交互使用类型明确的组件和 DTO，不得用通用键值表单或一套万能 Schema 页面替代。
- 普通配置表单、附加字段和适合通用渲染的插件界面优先使用 Schema UI，由主应用控制组件白名单、运行时校验、权限和主题。Schema UI 不负责复杂产品的核心组合校验、敏感凭证输入处理或最终计价，服务端仍须完整校验。
- 前端调用产品类型提供的可选项解析、配置校验和报价接口；选择条件变化后清理失效值并展示不可选原因。前端计算只能用于即时预览，订单金额、供应绑定和购买资格以服务端报价为准。
- 报价、订单和服务页面必须显示其创建时的产品类型及销售版本语义，不能以当前商品配置重新解释历史快照。密码、私钥等敏感值使用专用输入和一次性提交，不进入浏览器持久存储、普通表格、日志或可回显 DTO。
- 小型页面扩展使用受控 Slot，明确可传入的数据、可触发的动作及生命周期。
- 插件界面统一使用受信的预构建扩展、公开 SDK 和受控页面/Slot 扩展点，不要求 iframe。SDK 明确可用数据、路由、权限、动作和主题接口，不依赖主应用私有 Context 或内部 API；同域 JavaScript 按受信代码审核，运行时加载另列后续建设。
- 插件资源加载必须校验清单、版本、权限、来源和完整性，并支持禁用、失败回退及缓存失效。
- 独立插件页面和动作须经清单审核及宿主注册，不接受任意页面路径、组件名或处理方法；仅使用公开 SDK 的受控 DTO、请求和动作，不能获取私有 Store、Cookie/令牌或其他连接配置。不同应用按 React/Arco 版本检查兼容，前端与后端均执行授权；新运行时按后续阶段建设。

- 展示服务实例的 `status=active` 使用“已开通”，不解释为资源运行中；开关机状态由未来的生产能力单独提供。来源订单固定为首次交付订单，续费、升级等后续交易分别关联订单单位。

## 前端安全

- 不在源码、构建变量或浏览器持久存储中硬编码密钥、管理员令牌和生产凭据。
- 展示富文本、模板内容和插件消息时必须按信任边界进行转义、净化和来源校验。
- 权限控制不能只隐藏按钮；前端负责交互提示，最终鉴权与对象归属校验必须由后端完成。
- 上传前端需校验类型和大小并提供用户反馈，但不得把客户端校验视为服务端安全保证。

## 前端验证

运营后台常用检查：

```bash
cd admin
pnpm lint
pnpm build
```

会员控制台常用检查：

```bash
cd console
pnpm lint
pnpm build
```

在线安装器常用检查：

```bash
cd install
pnpm lint
pnpm build
```

- 修改共享包时，必须验证所有受影响的应用，而不是只验证共享包本身。
- 视觉或交互改动除 lint/build 外，还应通过浏览器检查目标页面、关键响应式尺寸、溢出、交互状态和控制台错误。
- 涉及路由、权限、请求缓存或插件加载时，覆盖直接访问、刷新、失败、无权限及禁用等边界场景。
