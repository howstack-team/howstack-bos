# 运营后台前端补充规范

本文件适用于 `frontend/admin/`，继承仓库根目录及 `frontend/AGENTS.md` 的通用要求。组件与视觉要求遵循统一的 Arco Design React 规范。

- 使用 React 18、TypeScript、Vite 8、Arco Design React 和 Arco Design Pro 主题。会员控制台与安装器也使用 Arco Design React，三者保持独立构建和路由。
- 布局和登录页以 Arco Design Pro Vite 官方模板为基础，保留 `Navbar`、`Sider`、`Menu`、`Breadcrumb`、`Content`、`Footer` 结构。布局组件及样式集中在 `src/layouts/`，共用权限、路由和页面内容；默认经典单列布局，可在页面配置中选择双列布局，选择保存于当前浏览器。经典侧栏默认 220px，折叠后 48px；双列左栏 88px、右栏默认 168px，折叠后保留一级列。两种布局都允许多个分组同时展开，一级菜单才配置图标。移动端使用可关闭的侧边面板，保留遮罩区域并支持 Escape；不得因切换布局重新加载业务状态或更改 URL。树形路由、菜单与 `requiredPermissions` 集中在 `src/routes.ts`，由 Webman 权限码转换为 Arco Pro 的 `resource/actions` 映射。
- 后台 API 继续遵循 Webman 的 `/api/admin/v1` 契约、统一响应外层结构与 HttpOnly Cookie；前端菜单过滤不是服务端鉴权替代。
- 系统版本分为社区版（Community）、专业版（Professional）、企业版（Enterprise）。安装后未配置商业授权时默认展示社区版，授权状态为“无需商业授权”，不展示为未授权或待接入。未来商业版本以服务端已验证的授权结果为准，接口异常不能擅自将已授权实例降为社区版，也不通过前端配置或浏览器存储启用商业权益。
- 授权与更新、应用中心只调用本机后台 v1 API；官网会员确认与付款通过后端校验的官网链接完成。前端不得接收实例私钥、官网令牌或设备密钥。检查失败不显示“当前版本已最新”，连接/购买确认不代表已授权或已安装；下载、安装、重启和人工恢复状态按本机持久任务展示。
- 登录后的更新提醒读取本机 `system-updates/notice` 缓存，仅向有更新查看权限的管理员展示。顶部提示和左侧“授权与更新”菜单的 Arco Badge 徽标共用同一次缓存查询；有可用更新时显示菜单徽标，无更新或无查看权限时隐藏。提供查看更新和二十四小时稍后提醒，稍后提醒只隐藏顶部提示；更新页同时展示日志、成功时间和失败尝试时间，不因接口失败或短期清单到期删除已验证摘要，也不以浏览器轮询触发官网检查。
- 新版本日志遵循官网 v1 的 `added/improved/fixed/notices` 四分类对象，只按文本展示，隐藏空分类。已验签 `force_update=true` 时持续显示要求更新的提醒，不提供“稍后提醒”、不受旧隐藏偏好影响；执行仍须管理员权限和确认，禁止自动升级或中断业务。版本变更说明称“更新日志”，本机执行任务历史称“升级记录”。
- 顶栏通知使用 Arco Modal 消息中心，桌面展示两级分类与消息列表，窄屏将分类改为选择区，保持列表独立滚动、分页和遮罩关闭。版本通知复用布局的本机已验证摘要，不额外触发官网检查；消息已读不能关闭强制更新提示。消息中心演示数据集中在 `src/mock/notificationPreviewData.ts`，仅开发环境按需加载并标明演示，不写入后端、不随生产构建交付；接入真实业务通知与持久化已读另行实现。
- 消息摘要在布局加载时读取，不等点击通知后才显示未读徽标；展开内容内的“查看详情”导航到对应后台页面，复用路由权限过滤，不在折叠标题中以同名链接代替展开操作。演示消息只跳转已存在页面，不请求虚构记录详情。
- 连接皓量云擎账号时不在本机选择版本或填写授权编号；官网根据软件配置和会员权益提供登记方式及授权选择。关联版本展示官网返回的 `edition_name`，版本代码不硬编码成三项枚举；连接信息不能代替已验签的商业授权或开启高级功能。
- 应用中心只读取当前实例已获取的应用，管理安装、更新、卸载及任务记录，不请求全量商店目录、不在后台提供领取或付款流程；官方应用商店使用本机后台生成的受信超链接访问。卸载沿用状态、业务引用、安装互斥和独立权限检查，保留配置及历史数据，不取消官网权益。
- 不提供独立的插件管理菜单、页面或 `/plugins` 路由；已获取应用的前端管理入口统一使用应用中心。插件启用、停止接单和停用目前通过后端维护命令执行，资源供应商配置页面只显示已启用的对接平台。
- 基础服务配置统一归属「系统管理 → 通道管理」，按支付、短信、邮件、实名认证、文件存储、第三方登录、人机验证设置固定入口。应用中心负责安装维护；通道页默认展示本地已校验的全部同类插件，未配置时也显示为禁用，直接配置及启停，不提供“新增通道”、平台选择、自定义通道名或删除入口。首次保存与编辑统一使用本类别 update 权限，另有 view 权限；邮件测试权限独立。名称、字段声明和可用状态从本机后端获取，不硬编码可运行的示例平台。未配置时点击启用引导先配置，平台不可用时只读保留已有配置并允许禁用；历史连接和业务引用不得删除或静默替换。私密字段只显示是否已设置，空输入保留原值，明确清除另传键名；启停不等于外部连通测试。动态配置使用 Drawer，字段较长时使用带 configure/connection URL 状态的完整页面。 短信和邮件显示后端返回的“主用通道”，文件存储显示“默认存储”；支付、第三方登录、实名认证、人机验证不显示统一默认列或开关。列表返回 default_label 控制显示，后端必须同步约束 is_default；多平台启用与业务实际选择分开，不静默切换历史绑定。
- 角色权限分配按 `routes.ts` 递归保留完整菜单层级，系统用户、部门管理、角色权限同属“组织与权限”；分组勾选联动所有后代页面，遵守当前账号可授予范围与节点关联/独立模式。分组仅用于展示与联动，不虚构后端权限码；保留未展示的历史授权，展开/折叠覆盖全部分组层级。
- 每新增一个页面，必须同步增加对应的后端权限码、Arco Pro 路由 `requiredPermissions` 和角色权限分配入口；页面内的新增、编辑、删除等操作还需各自的权限控制及服务端校验。验收至少覆盖允许访问、无权限拒绝，以及只有查看权限时不能修改。
- 通道管理七类页面不放搜索表单，固定插件目录直接展示，保留表头状态筛选和排序等既有操作。消息配置同样不放搜索表单，且不提供刷新按钮；编辑保存后自动更新列表。不支持的渠道使用空值交给表格展示，不手写“—”占位。
- 消息模板与发送策略统一归属「系统管理 → 消息配置」。社区版采用“发送给客户 / 发送给管理员”两个 Tab，固定消息目录完整展示，不分页、不搜索、不刷新；表格显示消息类型、描述、各渠道启用状态与文字编辑操作，不展示接收组、用途分类或策略管理。编辑使用单列 Drawer，Tab 按当前消息支持的渠道展示，只配置渠道开关、发送通道和模板；不提供接收组增删排序及部门/角色范围设置。底层多接收组、修订、队列、幂等和日志能力保留，不能以简化界面删除或覆盖已有精细策略；多组或自定义范围的对应渠道在抽屉只读保留，未编辑渠道及另一受众原样保存。批量配置作为当前受众的全局配置入口，在 Tab 右侧提供带图标且无需表格勾选的按钮；表格不显示选择列。弹窗先选择渠道，再显式选择适用消息，默认不全选，选择区支持全选并展示修改数量；切换渠道清空已选消息和通道引用。仅列出支持当前渠道且明确匹配的消息，不再选择接收组类型；保留原模板和范围，无匹配时不静默跳过。机器人凭据引用「系统设置 → 消息通知」，无可用通道按权限提醒引导。保存不发送，公众号发送尚未接入；注册验证码使用独立发送服务；日志继续区分总体结果、渠道投递与尝试。商业版扩展需要另行实现服务端权益校验，不能仅靠前端显示高级入口。
- 消息日志面向社区版运维排查：列表显示接收对象而非接收组名称，精细组信息保留在详情；查询区仅保留场景、渠道、发送结果、记录时间四项常用条件，消息类型通过表头筛选；保留查询/重置和右上刷新。发送结果按完整消息聚合，日期包含结束当天；底层保留接收对象、投递结果及关联业务等高级查询能力，普通页面不铺开。详情默认展示渠道结果、绑定通道名称快照、失败原因和最后更新时间，尝试记录折叠；不以当前配置补写历史通道名称，不将更新时间当作送达时间。已读仅展示在站内渠道，未知结果不能重试，查看和筛选不能触发发送。
- 产品管理按已实现业务设置固定入口。云服务器是一个固定产品，在「产品管理 → 云服务器」下设置地域和可用区、规格与套餐、线路和网络、镜像和存储、购买与计费五个三级菜单和独立路由，不提供产品列表或新增产品；规格组、镜像分类和防护归入对应区域；页面不再重复五个主区域 Tabs，页面内分类使用 Arco `Radio.Group type="button"`。配置上下文及编辑位置使用受控 URL 参数；跨配置页面共用草稿，离开配置范围提示保存。每页独立 view 权限，共用既有资源及配置操作权限；旧链接兼容重定向。配置只提供保存和预览，不提供手动发布；完整保存自动生效，缺项保存并提示原因，历史订单和快照不变，保存不能重新启用已明确停用的配置。云服务器配置工作台及其管理抽屉内的表格不放搜索表单，也不使用隐藏的名称/标识查询条件过滤数据；可用区、线路及资源对应选择仍作为配置上下文保留，表头筛选、排序和分页继续按业务使用。社区版直接编辑一份配置，不提供销售方案新建列表或独立交付规则入口；已有多份配置须明确选择，禁止自动合并或覆盖。提供者按可用区选择，资源对应与高级参数在上下文中配置；旧版网络仅保留后端历史读取，共享资源供应商同属产品管理；已开通实例仍属于业务管理。
- 面向客户的文案使用业务名称和明确的操作说明：供应连接展示为“资源供应商”，适配器展示为“对接平台”，目录与映射展示为“资源对应”。避免在日常操作界面展示 SDK、清单、快照、凭据等实现术语；代码、接口和开发文档保留准确技术标识。
- 云服务器可复用配置的部署关系使用多选，与后端 `zone_ids/line_ids` 保持一致；规格组 CPU 型号与频率、镜像最低配置、存储读写参数标明单位及选填语义。带宽阶梯界面分别解释“按区间累进”和“按整段单价”，费用以服务端为准。可用区提供者与供应商页复用资源对应组件，并独立遵守供应查看、目录读取和修改权限；交付参数预览明确不创建实例。
- 业务页面使用 Arco 的 `Table`、`Form`、`Modal`、`Drawer` 等组件，不引入 Ant Design 或 ProComponents。生产构建写入 `backend/public/admin/`。
- 后台价格和金额以元展示及输入，不向用户要求填写分。价格输入统一调用 `src/components/PriceInput.tsx`，使用 Arco 原生 `prefix="¥"` 和单位 `suffix`（元、元 / GiB、元 / Mbps 等），最多两位小数。组件 value/onChange、表单状态、API 与数据库仍使用整数分，通过 `src/utils/money.ts` 精确转换；禁止直接浮点乘以 100，不能改变已有金额或误将分当成元。回填、零价、分项/阶梯价格、清空和上限须验证；其他币种保持准确的币种标识。
- 运营后台所有图表统一使用 VChart，包括趋势、分布、占比和关系等数据可视化；不要使用 Ant Design Charts、ECharts、Chart.js、Recharts，也不要手写 Canvas、SVG 或用静态图片模拟图表。单个数值或状态展示按 Arco 组件和页面排版处理。本规则仅适用于运营后台，会员控制台与安装器仍遵循各自的图表规范。
- 表格查询区统一使用 `TableQueryForm`（Arco `Form layout="inline"`），字段用 `Form.Item` 组织，并遵循前端通用“表格查询表单规则”：查询区独立一行，查询/重置位于行尾，与下一行工具栏分开；高频字段常显，其余按复杂度折叠或使用高级筛选，窄屏保留一个高频查询字段及筛选入口。应用/重置条件时页码归 1，重置后重新查询；回车与查询按钮行为一致，实时搜索约 300ms 防抖。已应用条件及分页同步 URL，刷新、分享、详情返回和前进/后退均保留状态；不将查询表单和编辑表单嵌套。
- 查询条件使用独立业务字段并由后端按 AND 组合过滤；`TableQueryForm` 提供查询、重置、折叠/筛选入口，`useTableQuery` 管理待填写条件、已应用条件和 URL 分页状态。不得只提供通用关键词或在当前页数据中伪装服务端组合筛选。
- 表格列遵循前端通用“表格列排序与筛选规则”：有比较需求的时间、金额、数量、容量、优先级等列增加排序，选项有限的状态、类型等列增加筛选；按业务判断，不给所有列机械添加入口。服务端分页必须接入接口的完整数据集排序/筛选，不能只处理当前页。列筛选与查询表单共用已应用条件，同字段入口同步，排序和筛选状态受控并保存到 URL；变化时页码归 1，重置清空筛选并恢复默认排序，保留既有权限、加载及请求竞态处理。
- 表格工具栏遵循通用规范的“左批量、右全局”分区：选中数量及批量操作靠左；新增/创建等主操作、导入/导出全部等全局操作及刷新、列设置、密度、全屏等辅助工具统一靠右，辅助工具始终位于表格右上方。查询表单与工具栏按职责分组，不因复用 `TableQueryForm` 将刷新等辅助工具混放到左侧查询区；没有批量操作时仍保留右侧工具的位置，全后台同类操作保持一致。
- 表格操作列统一使用 `TableActions`，以 Arco `Space size="mini"` 排列文字 `Link`，操作项不添加图标。按权限过滤后的实际操作项不超过 3 个时全部直接显示；达到 4 个时直接显示前 3 个，从第 4 个起放入由文字“更多” `Link` 触发的下拉菜单，菜单项同样使用文字。需要折叠时优先将删除、停用、重置凭据、分配权限等敏感操作排在“更多”中；不足 4 项时不单独为敏感操作显示“更多”，执行前仍保留必要的二次确认。图标规范适用于表格上方查询区和工具栏的按钮，包括查询、重置、新增、刷新、批量操作和辅助工具；操作列按文字内容设置合理宽度并保持单行。
- 表格状态列若只有“启用 / 禁用”两种状态，单独沿用原有样式，统一调用 `src/components/EnabledStatus.tsx`，不改为 `Tag` 或 `Badge`。组件以 Arco 的 `IconCheckCircleFill` 配成功色展示启用、`IconMinusCircleFill` 配警告色展示禁用，并附文字。遵循当前 Webman 契约：`1` 为启用、`0` 为禁用；不能照搬其他示例中的 `2`，也不能将未知值直接当作禁用。其他业务状态不套用此组件。
- 其他表格分类和状态遵循前端通用“表格分类与状态展示规则”：订单类型、产品类别、认证类型等没有好坏之分的分类保持纯文本；每个表格尽量只有一列主要流程状态使用 `Badge status/text` 的圆点加中文文字，辅助状态使用纯文本，例如订单状态用徽标、支付状态用文字。按业务语义集中维护枚举文案及配色，并与查询、表头筛选一致；保留原生尺寸，不使用数字计数徽标表示流程状态，不把所有字段机械包装成标签。启用/禁用及账号绑定等已有专项图标文字规则继续沿用。
- 表格中名称、描述、地址等内容可能超过列宽时，为对应列设置合理宽度及 Arco `Table` 列的 `ellipsis: true`，保持单元格省略显示；需要阅读完整内容时提供悬停提示或详情入口，不直接截断原始数据。短内容列和操作列不机械添加省略。
- 表格数据单元格为 `null`、`undefined` 或空白字符串时统一显示半角 `-`；`0` 和 `false` 是有效值，不能当作空值。具有明确业务含义的文案（如“待分配”）保留原样。操作列没有可执行操作时留空，不显示占位符。
- 普通列表表格默认每页展示 20 条，可切换为 10、50 或 100 条；服务端分页切换条数时重置到第 1 页并按新条数重新请求。部门树、权限树和不足 20 条的固定展示表格保持完整展示，避免拆散层级或添加无意义分页。
- 表格分页通过 `ConfigProvider.Table.renderPagination` 统一接入 `ResponsiveTablePagination`；根据分页区域实际宽度自适应，窄屏首行展示总条数与每页条数，第二行使用 Arco 原生精简分页。保留 Table 的客户端数据切片、服务端分页回调和筛选语义，不能用样式覆盖组件内部结构，或让分页随表格横向滚动产生溢出。
- 普通列表表格只通过 Arco `Table.scroll.x` 管理横向滚动，纵向随主内容页面自然滚动；外层 `.table-scroll` 不再设置 `overflow: auto` 或 `overflow-x: auto`，避免分页或固定列的少量溢出产生额外纵向滚动条。除明确需要固定高度的独立面板外，不设置 `scroll.y` 或限制表格高度。
- Modal 表单中的状态字段若只有“启用 / 禁用”，使用 Arco `Switch type="round"` 并显示对应文字；通过表单值转换保持接口的 `1`（启用）和 `0`（禁用）契约，编辑回填与提交均不得变成布尔值。
- 表单容器遵循前端通用决策规则。分类、部门、角色基本信息、工单类型、分组/等级及简单资源等短表单复用 `FormDialog` 的窄单列 Modal。会员、系统用户等中等 CRUD 明确使用 `mode="drawer"`，单列并保留列表上下文；镜像/规格/网络参数、供应商动态配置、提供者高级参数继续使用 Drawer。新闻/帮助正文及资源供应商页面的资源对应使用 `PageFormEditor` 完整页面。云服务器配置工作台的地域/可用区管理、资源新建编辑（含线路、存储类型）、资源对应、库存与高级参数统一使用 Drawer，保留工作台背景和当前 Tab，不切换为单页；编辑与资源对应继续通过 `useEditorLocation` 的 `edit` / `mapping` 查询参数保存。管理抽屉内的新增、编辑使用 `FormDialog mode="modal"`，不得自动升级为第二层 Drawer；关闭子 Modal 只关闭子编辑，保存后更新父抽屉列表。手机不一律改为抽屉；轻量 Modal 仅在实际放不下时自动转换。字段数不作为硬阈值，不得恢复 `ModalFormBody`、嵌套浮层或弹窗内部滚动表单。
- 保留当前品牌蓝 `#165DFF` 与矩形 `2px` 圆角要求；业务自定义样式避免阴影、渐变、拟态玻璃和悬浮抬升。官方模板的原生布局样式保持默认，不覆盖组件私有 DOM。
- 至少验证桌面端与 390px 移动端，覆盖菜单、表格横向滚动、弹窗和抽屉。
- 每次改动运行 `pnpm lint` 与 `pnpm build`；接口流程还需验证真实 Webman 服务、数据库和权限状态。

## 内容正文编辑

- 帮助文档使用 ByteMD 和 Markdown；新建新闻公告使用 Tiptap 富文本。正文格式显式通过 `body_format` 传递，旧 Markdown 公告保留原文，仅在用户主动转换并保存后变更格式。正文编辑使用独立页面，编辑器按需加载。
- HTML 正文必须服务端白名单清理，前端展示也使用 DOMPurify；不得直接渲染未经清理的 HTML。图片上传复用本机公开素材接口及默认存储通道，不把临时签名地址保存到正文，也不上传私密附件。实现约束见 [内容编辑器](../../docs/development/content-editors.md)。

- 会员注册支持手机号或邮箱加密码，两种方式与各自验证码要求由系统设置控制；`register_verification` 支持短信和邮件，`login_verification` 仍只允许短信渠道。目录、单条及批量配置保持一致；注册验证码由独立服务校验有效期、单次消费和频率限制，不经过普通通知队列或消息日志。对外会员 ID 使用八位固定随机数字，列表按注册时间及内部主键稳定排序，业务外键仍使用内部主键。

- 云服务器新配置使用包年包月v2，周期按可用区独立维护月数、显示名称和优惠，购买配置器切换可用区须联动周期，不能共用全局折扣；上下行、赠送、阶梯和IP归线路完整编辑页面。旧方案保留原契约，不能自动把单带宽转为上下行。规格库存通过当前可用区的操作列入口设置并显示可售数量；价格仅在对应规格、存储类型、线路、防护位置维护，购买区不重复设置覆盖价；数量和周期归购买区，不提供一次性费用输入，新配置默认不收取此费用。通用计费字段保留，历史非零费用须明确展示金额并允许主动取消后保存，不静默隐藏或修改历史计价；默认系统盘和挂盘限制归存储区；价格/容量用原生后缀；配置预览不代表已开放会员下单或生产。交付参数对应只使用标准字段及受控转换，不支持凭据或可执行表达式。

- 多分组配置表单的分组标题复用 `SectionTitle`，整行浅灰标题栏配主题色竖线（3px × 16px、间隔 8px），标题栏约 32px 高、内边距 4px 12px，保持原有标题语义与字号；授权与更新页及各配置分组统一使用，不为不同页面另做颜色。

- 财务管理列表只展示真实单据，不将空列表自动替换为可操作的演示交易。线下充值、退款、开票及提现分别校验创建、审核和处置权限；工具栏全局操作带图标，操作列使用文字链接。资金操作以整数分提交，以元输入，明确可处理额度及外部登记语义；只读保留未核对的历史单据。禁止在前端直接修改支付成功、账户余额或流水，具体规则见 `docs/development/finance-foundation.md`。

- 云资源的关联可用区使用 Arco `Cascader`，按“地域 → 可用区”组织，关联字段支持多选，页面上下文/库存/周期使用单选。界面路径与数据契约分离，表单和 API 仅提交叶子可用区 ID 或 ID 数组；不得提交地域 ID、完整路径或显示名称。已有关系准确回填，空地域不可选，失效关系须明确提示而非静默删除。

- 云服务器“购买预览”、配置记录及启停配置的全局入口集中在“购买与计费”，其他四个资源页面不重复显示。资源编辑在抽屉中保存；购买范围、提供者及存储规则仍共用受控草稿，其他页面仅在有待保存更改时于底部显示“保存更改”。切换配置页面保留草稿，保存失败保留输入及保存入口，成功后收起待保存操作栏；不要为减少按钮而静默保存、丢弃更改或取消必要的保存入口。

- 官网入口为「内容管理 → 官网管理 → 基础设置 / 导航管理 / 页面 SEO」，统一主题管理作为内容管理下的独立二级页面。基础设置维护品牌图片和公司资料；页面 SEO 独立维护首页副标题与逐页标题、描述、关键词；导航单独保存，主题管理提供安装、统一切换整套主题，缺少组件使用default及主题专属配置；每个主题只有当前安装记录，同ID包作为更新，版本号仅展示为资料，不提供版本记录或版本选择，不提供预览。公共资料不在主题中重复录入，切换主题不丢失；分区保存不提交其他页面字段，409保留输入并提示重新加载。

- 公开素材统一归属「内容管理 → 文件管理」，按类型、来源和原始文件名过滤，支持素材选择与引用保护。文件类型图标使用后台本地 `src/assets/file-types/` 的素材，按扩展名匹配并保留来源说明；图标覆盖范围不等于上传允许范围。正文和官网保存引用前服务端再次验证素材，私密业务附件不进入公开文件库。

- 主题管理直接在卡片操作，不提供顶部主题选择表单或独立保存按钮。未使用主题提供“启用”，当前主题标记“使用中”并展示移动端开关；切换和开关即时通过同一绑定 API 保存，切换主题默认关闭移动端，须在新主题卡片明确开启。没有实际会员mobile模板（含default整组件回退）时禁用开关并说明原因。PC模板必备、移动模板可选，不展示responsive类型；失败不提前改变已保存状态，409提示重新加载后重试。官网展示配置仍使用抽屉并保留未保存修改。

- 当前主题配置仅开放官网，不显示官网、PC版、移动端配置切换；仅提供会员中心的主题不显示配置入口。底层保留组件级配置 API、存储与校验契约作为未来扩展边界，不因包内存在会员配置声明自动开放后台入口。
