# 社区版 1.0 上线范围与验收清单

基线日期：2026-10-18。适用仓库：`howstack-bos`。

**社区版 1.0 冻结新增功能，目标是交付能够真实销售、收款、开通、续费、运维和处理售后的云服务器业务系统。工单是正式保留功能，必须补齐会员与后台之间的完整会话闭环。当前处于收尾阶段，尚未达到发布放行条件。**

## 一 冻结规则

允许继续的工作：修复缺陷、安全整改、完成下文列明的必补功能、三端接入、自动化验证、真实平台联调、发行包和部署文档。新增产品类型、商业扩展、营销能力和主题架构调整暂停，除非用户明确调整范围。

1. 首发正式支持一种产品：**包年包月云服务器**；固定带宽、密码登录、人民币计价。按量、密钥、升降配等只保留代码边界，不开放入口。
2. 先验收一个真实魔方云版本和一套供应连接。可以配置多个地域、可用区；不把多提供者、采购转售或供应迁移作为首发目标。
3. 付款主线固定为：**在线充值到账 → 明确确认余额支付 → 逐实例开通**。至少验收一个真实支付通道，不新增商品直接在线支付或 H5/JSAPI 协议。
4. 官网使用默认自适应模板；会员中心保留默认 PC 和独立移动模板。两端均完成主线业务，不再增加新的布局体系和模板类型。
5. 认证、消息、支付和供应插件只开放实际配置有效且完成相应验收的能力。不为了凑齐通道数量增加适配器。
6. 社区核心独立运行，不要求激活商业许可证、连接商业官网或购买插件。Pro、Enterprise 保留边界，暂停功能下发及高级能力建设。
7. 试用、自动扣款续费、到期销毁等不纳入首发。**到期暂停保留，自动删除数据不开放。**

### 工单的最小闭环

R03 实施前只有后台类型、快捷回复、工单查询与回复，PC/移动尚未接入。现在下列开发闭环已补齐，仍作为发行候选的验收要求保留：

- 会员选择启用的类型，填写标题和正文提交；可选关联**本人**云服务器，不得枚举其他会员资源。没有可用类型时明确提示联系运营方，不产生无效工单。
- 本人列表分页、状态筛选、完整会话和追问；列表默认每页 20 条，会话分页或限制单次读取数量，避免长会话无限加载。后台复用既有列表、详情和快捷回复。
- 沿用现有状态契约：`open`（等待后台）、`processing`（处理中）、`waiting_member`（等待会员）、`closed`（已关闭）。新建与会员追问进入 `open`，后台回复进入 `waiting_member`；既有 `processing` 记录继续正确展示。双方均可关闭，已关闭不再回复。1.0 不新增状态枚举或重新打开流程。
- 新建、回复、关闭有认证、归属、同源、输入长度限制、频率控制和重复提交保护；后台回复、关闭独立授权并审计。状态变更与消息写入保持事务一致。
- 后台回复产生本人站内通知，消息链接打开正确工单；提醒通知失败不能丢失已提交会话。后台已有列表可发现新工单，不新增实时推送系统。
- 正文采用安全文本或受控 Markdown，不执行任意 HTML；不开放工单附件，不把私有售后资料存入公开文件库。

关闭只结束沟通，不代表已退款、已释放资源或问题自动解决。退款、资源操作沿用各自独立权限和确认流程，工单不能直接执行扣款或运维。

### 隐藏的实施要求

1. 同步处理后台侧栏、PC 侧栏/顶栏、移动底栏/“我的”、首页快捷入口、官网导航及消息中的跳转；不能只改一处菜单。
2. 直接访问隐藏的新业务页面应返回明确的不可用页或 404；涉及暂不支持的**新写操作**由服务端拒绝。保留必要的历史读取、支付通知、原查单及存量任务收尾，不能一刀切禁用整个模块。
3. 首发范围与 RBAC 分开：隐藏不是授权，恢复菜单不能绕过服务端权限。复用集中路由和现有能力判断，不为本次收口新建版本授权或功能下发系统。
4. 不删除数据库表、已执行迁移、财务事实或用户文件，不把历史数据清空作为上线步骤。

### 必补范围的限制

- R02 只做**本人只读资金明细**，不增加完整财务门户、账单下载或复杂筛选。
- R03 只做工单沟通闭环，不以此建设审批平台或客服工作台。
- R04 复用已有后台审核、余额退款、来源批次及人工打款凭证能力；不得通过直接修改数据库余额或供应任务状态办理。
- R05 至少一个支付渠道通过即可。移动端现有 Native/扫码协议不等于同设备 H5 支付，须实际验证二维码保存/扫码流程并如实提示；不可用的方式隐藏，不假装已支持跳转支付。
- R06 到期资源保留、不自动删除。供应平台上长期保留的成本和人工释放流程须明确，不把这件事扩大为新的自动回收系统。
- R08 优先落地一种 Linux 部署方式及人工升级步骤，不要求同时建设 Docker、Kubernetes 和自动发布平台。
- R10 只要求首发承诺及仍暴露的接口完整；延期模块不因既有文档缺口被临时扩成新功能。不能通过新增豁免掩盖保留业务的结构缺失。

## 七 收尾顺序与放行条件

按下面的顺序实施，真实商户、短信/邮件与供应测试环境的准备可以同步推进，不启动新的功能线。

1. **范围收口 R01**：固定首发入口和后台支持边界，工单、资金明细列为明确必补，其他延期功能统一隐藏。
2. **补齐日常闭环 R02～R04**：本人资金明细、三端工单、可执行且受控的失败交付退款/资金清退；同步补 API 契约及权限。
3. **完成外部联调 R05～R07**：真实收款、真实资源、实际验证码与提醒；只修复既定范围内暴露的问题。
