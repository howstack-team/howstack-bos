# 社区版云服务器配置工作台

## 页面结构

云服务器是固定产品。后台直接进入一份配置，五个配置页面位于「产品管理 → 云服务器」的三级菜单：地域和可用区、规格与套餐、线路和网络、镜像和存储、购买与计费。路径为 `/products/cloud-servers/{deployment|specification|network|storage|purchase}`，页面内分类使用按钮式单选。分类、可用区、已有配置选择和编辑位置写入 URL；切换页面保留当前未保存草稿，离开配置范围提醒保存。原路径及 `tab` 参数兼容重定向。

| 主分区 | 内容与布局 |
| --- | --- |
| 地域和可用区 | 左侧地域列表、右侧对应可用区表格；表格维护参与购买范围，从可用区打开提供者配置抽屉。地域管理抽屉内用 Modal 编辑。 |
| 规格与套餐 | 按可用区配置规格、套餐与库存，硬件分组显示 CPU 型号与频率。 |
| 线路和网络 | 按可用区管理线路，线路编辑包含上下行带宽、赠送值、阶梯、IP；防护在对应线路下配置。 |
| 镜像和存储 | 镜像、镜像分类及存储类型；默认系统盘类型 / 容量、赠送系统盘容量和数据盘上限归存储区域。 |
| 购买与计费 | 单次购买数量上限，以及按可用区独立设置的月数周期、显示名称和周期优惠。分项价格回到资源位置维护，不另设覆盖价表格。 |

购买与计费页面顶部提供保存配置和购买预览，配置记录与停用收进辅助菜单；其余四页只展示资源操作，不重复全局入口或配置生效状态。有未保存的购买范围、提供者或存储规则时，在这些页面底部显示“保存更改”，成功后收起，失败保留输入与保存入口；资源保存后的购买配置更新同样由此提交。切换页面继续保留共用草稿，不做静默保存。不展示发布按钮或待发布流程。缺项提示位于内容底部并定位需要补充的可用区和区域，完整配置不再展示提示。规格、网络、镜像和存储统一分类与可用区上下文栏，选择使用「地域 → 可用区」级联组件；硬件及镜像分组全局维护，不机械套用可用区。购买规则与默认盘规则限制字段宽度，周期仍使用整行表格。

## 数据与兼容

- 社区版不提供销售方案列表、新建销售方案或独立交付规则界面。底层销售版本、共享库存与供应契约保留，供未来版本扩展。
- `products.workspace_configuration_id` 表示显式默认配置。GET 不写数据；只有一份历史配置时可以直接读取，存在多份且未设置默认时必须明确选择，保存后设置指针。
- 首次保存先锁固定产品，禁止重复初始化。保存时同时校验默认指针与配置 revision；冲突返回 409，不覆盖并发修改。
- 草稿可选 `zone_provider_bindings`：每个可用区选择提供者及参数规则。发布校验实际可用资源和映射，再封存 `provider_bindings.zone_bindings`。
- 历史单连接绑定、交付规则及发布快照继续按原语义读取；没有显式可用区绑定的旧配置使用原提供者逻辑。旧版网络不再提供正常配置入口，其历史记录不删除。
- 旧 v1 配置须明确转换为包年包月；不会自动把单带宽转换为上下行。历史周期与价格快照不重写。

## 保存与生效

社区云服务器不提供一次性费用输入，新配置默认 `setup_minor=0`。通用计费字段及历史计价能力保留；已有非零配置显示金额和明确提示，可主动取消后保存。只读账号只能查看，取消前不静默修改，已生效版本和历史订单金额不改写。

资源表单和库存即时保存；参与购买范围、提供者选择、默认存储和购买规则统一点击保存配置。保存完整配置后自动记录生效版本，无须手动发布。配置缺项只保存输入并返回 configuration_ready=false 与 configuration_notice，旧生效版本保留；用户完善后再次保存自动生效。

保存生效前校验资源组合、价格、存储、线路及提供者对应；新增使用 create，已有配置使用 update，无须 publish 权限。首次完整保存自动启用；已明确停用的既有配置保持停用。权限、并发及系统异常整笔回滚；配置缺项允许保留输入。预览只试算和生成提供者参数，不创建订单、扣费或开通实例。

发布版本不可变。旧版本的价格、映射与可用区提供者独立于后续草稿；停用操作不丢弃未保存输入。

## 后续边界

按量计费、流量计费、密钥登录保留契约边界，不开放社区配置入口。试用、退款、自动续费等尚未执行的策略不在社区主页面展示；完整目标仍见 [云产品平台架构](cloud-product-platform.md)。会员购买、财务、营销和真实履约需另外实现并验证。

## 可用区付费周期

- `draft.zone_durations` 按 `zone_id` 保存各区的周期、名称、折扣或等效计费月数；相同月数在不同区可以采用不同优惠。购买与计费中选择当前可用区编辑，切换不丢失其他区输入。
- 后台读取旧草稿时将原全局 `durations` 独立复制给已有可用区，首次保存后采用可用区配置；新增区默认月付、季付、半年付、年付且均为原价。取消参与购买的区同时移除对应草稿周期。读取不会写数据库。
- 保存允许尚未配齐可用区，保存生效必须覆盖所有参与购买的可用区；重复可用区、区内重复月数、无效折扣或范围外可用区均拒绝。显式 `zone_durations` 缺少规则时不能回退到全局周期。
- 新发布封存每区周期；未选有效可用区不返回周期。切换区清理原周期并联动当前区选项，计价、订单及交付都按选中区查周期与优惠，客户端不能使用其他区的周期。
- 未包含 `zone_durations` 的旧发布版本仍读取原全局周期；修改草稿和重新发布不重算既有订单。该变更复用草稿和版本 JSON，不改表结构、不回填历史数据。

### 页面访问权限

五页分别使用 `admin.cloud-configuration.{section}.view`，并依赖既有资源查看或购买配置查看权限。页面通过 `GET /cloud-servers/sections/{section}` 同时校验页面和数据访问权限；仅查看不授予写入。角色分配按三级菜单显示，选中页面补齐依赖查看权限；资源新增/编辑仍是共用操作权限，配置新增/编辑/预览归于购买与计费，服务端继续逐操作校验。迁移 20261008000800 按原查看范围添加对应页面权限，不修改既有操作授权及配置数据。

20261008000900 将原部署与规格访问范围补齐到新增规格与套餐页；GET 不写入配置。社区保存生效使用 PUT /cloud-servers/configuration/live，旧草稿保存和发布 API 保留兼容，不改写历史订单或历史快照。

### 可用区级联选择

关联可用区使用 Arco Cascader 多选，按地域分组，仅保存叶子可用区 ID 数组；页面上下文、库存和周期编辑使用同一组件单选。地域与可用区节点使用不同前缀，避免 ID 相同导致路径冲突。空地域不可选择；缺失关联以失效项回显，不静默删除原值。选中地域时保存该地域下的可用区，不保存地域 ID 或前端路径。
