## 当前实现

| 模块 | 已实现的职责 |
| --- | --- |
| 官网连接 | 独立安装 UUID 与 Ed25519 密钥、授权码激活、安装签名、许可上下文、解绑与名额租约 |
| 授权 | 默认社区版；原始字节验签、实例与连接绑定、细粒度使用及更新权益、有限离线租约、修订防重放、撤销、时间回退和原业务证明 |
| 在线更新 | 当前代码版本、后端定时检查与已验签摘要缓存、登录后顶部提醒及稍后提醒、更新日志、确认时重新获取短期清单、明确目标确认、持久任务、下载完整性、包预检、维护、备份、前向迁移、完整重启及运行状态核对 |
| 应用中心 | 当前实例已获取应用、官方商店外链、本地状态、供应插件安装/更新/卸载、官网结果上报 |
| 管理边界 | 页面与操作 RBAC、同源写入校验、管理员及 IP 审计、状态和敏感数据白名单 |

后台页面：`/admin/maintenance` 同页展示授权信息、版本信息及升级记录，以及 `/admin/application-center`。授权码通过“授权码激活”弹窗填写。自定义后台入口沿用项目已有路由规则。

应用中心只同步当前实例已获取的应用，展示本机版本、可用版本、状态、安装与更新任务，提供受权限控制的卸载入口。浏览和获取应用统一通过“官方应用商店”超链接前往官网；`GET /application-center/store-link` 根据已校验的 `portal_origin` 生成 `/applications` 链接，未连接账号时也可使用，不附带凭证。后台不再提供旧 catalog/checkout API，也不保留对应购买权限；应用获取与结算由官网完成，后台只引用当前已获取应用及固定商店入口。

`POST /application-center/uninstall` 使用独立 `admin.app-center.uninstall` 权限、安装互斥锁及插件记录 `revision`，复用宿主状态机与业务引用保护。卸载登记为 `uninstalled`，保留服务器插件文件、配置、权益及历史记录，不删除客户数据。已启用插件应先在插件管理中停用；存在供应商或历史业务引用时禁止卸载。重新安装已卸载应用时备份并校验保留目录，不能覆盖未登记的已有目录。主题及其他类别的自动安装仍按对应运行契约建设状态开放。

账号连接、许可证、应用权益、文件安装及运行状态是不同事实。官网连接成功不会自动赋予专业版或企业版能力；安装结果由本机任务确认，不采用官网记录中的安装状态代替。没有配置商业授权时为社区版，不显示“未授权”。

后台填写秘密授权码，官网依据其对应的订阅核对会员、软件和名额，自动绑定本机安装UUID及公钥。不会要求客户在官网二次确认、手工登记UUID或选择授权编号。连接返回的 `edition_code`、`edition_name` 按官网实际配置校验和展示，不限定为社区版、专业版、企业版三项。自定义商业证书的版本代码和可选名称必须通过签名校验；功能资格来自签名 `grants`，购买版本不直接授予功能；能力目录与到期操作策略由宿主代码登记。

高级功能调用 `CommercialFeatureGateInterface::require(capability, operation, context)` 后仍须执行自身 RBAC、对象归属及业务不变量校验。本轮没有把现有社区功能改为收费功能，也没有提供虚构的专业/企业业务功能；具体高级能力开发时注册稳定功能标识。

商业证书的 grants 分别保存使用期限、更新期限及明确的永久标记；offline_until 是独立的有限联网租约，首期最多七天。使用到期、明确撤销、离线截止和时间回退分别限制新增高级操作；有效受理时生成并绑定业务范围的加密证明可用于历史读取和存量收尾，不能用于新批次或扩大配置。网络失败保留原证书和最近安全错误，在已验签期限内使用本地权益。固定维护进程通常每六小时尝试刷新，接近联网期限时提前刷新，失败后至少间隔十五分钟再试；无连接和社区版不请求商业证书。

## 官网接口

现行服务端为同级howstack-website，许可、激活、续签、更新清单、包下载及软件任务登记/报告已接通。具体见[客户端OpenAPI](../../../howstack-website/contracts/openapi/client.v1.json)。

应用中心保留本机运行接口，其官网权益、下载和回报尚待新官网实现；不会模拟已购买或安装成功。商业证书使用GET只读、POST刷新，验证原始字节签名、期限及高水位。
软件更新接口已按官网最新 v1 接入：`GET /api/client/v1/software-updates?architecture=...&current_version=...&platform=...&role=system` 返回签名 `manifest`；下载使用签名载荷中的 `/software-packages/{type}/{id}?architecture=...&current_version=...&platform=...&role=system`。应用中心的官网业务仍为预留。

详细载荷、签名、错误语义、更新包格式和验收要求见 [官网接入要求](official-platform-v1-requirements.md)。现有许可证 HMAC 更新接口与实例 Ed25519 协议不能混用。新接口缺失、网络失败和没有更新分别处理，失败不会显示“已是最新版本”。

## 部署配置

接入配置统一在 `backend/config/official_platform.php` 中设置，不再读取 `OFFICIAL_PLATFORM_*` 环境变量，也不在浏览器保存官网凭证。填写该文件的对应字段：

```php
'origin' => 'https://official.example.com',
'portal_origin' => '',
'trusted_license_keys' => [
    'license-2026' => '可信交付的 Base64 Ed25519 许可公钥',
],
'trusted_release_keys' => [
    'release-2026' => '可信交付的 Base64 Ed25519 公钥',
],
'download_hosts' => [
    'packages.example.com',
],
'private_directory' => base_path('storage/private/official-platform'),
```

- 修改后完整重启 Webman，使 HTTP Worker 与维护进程使用一致的配置。该文件已受在线更新保护，更新包不得覆盖客户配置。
- 正式部署使用 HTTPS 源站并关闭本地 HTTP 开关。HTTP 仅在 `APP_ENV=local`、将文件顶部的 `$allowLocalHttp` 设为 `true` 并指向本机地址时可用。
- 本地联调使用 `origin=http://127.0.0.1:8808`、空 `portal_origin`、显式本地HTTP开关与 `APP_ENV=local`；许可和发行公钥分别核对howstack-website。正式部署关闭本地HTTP开关，替换正式HTTPS地址及两组受信公钥；未配置的外部下载域名继续禁止重定向下载。
- 公钥是预置信任来源；远程接口返回的新公钥不会自动加入信任。密钥轮换先交付公钥，再签发新包。
- 下载跳转仅允许白名单 HTTPS 域名，最多三次；安装签名和身份头不转发到对象存储。
- 私有目录默认 `backend/storage/private/official-platform`，禁止放入 `public/` 或经符号链接改变存储位置。目录权限 `0700`，密钥和备份文件 `0600`。
- 私有卷必须与数据库一起备份并在容器更新后保留；不能重新生成身份去规避授权绑定。数据库内授权证书及状态使用现有 `APP_KEY` 加密；授权码只在激活请求提交，不持久保存。原令牌及配对状态在接入时清理。
- PHP 需具备 Sodium、ZIP、PDO 驱动及 `proc_open` 能力，维护进程具有受控文件写入和重启权限。发行包预装 Composer 依赖及前端产物，客户服务器不执行 Node.js 编译。

本轮复用既有 `20261004000200_create_official_platform_tables.php` 的私有状态表和维护任务表，BOS不新增业务表。新官网增加授权码及软件任务迁移。已有BOS部署按项目现行命令迁移并重启：

```bash
cd backend
php webman system:migrate --force
php start.php restart -d
```

新增配置、路由及 `software-maintenance` 进程必须完整重启后生效。维护进程每十五秒调度一次固定的 `php webman software:run`；每轮至多执行一个任务，不接受远程命令。

## 自动检查与提醒

- 官网 v1 的 `changelog` 为 `added/improved/fixed/notices` 四分类对象，软件和应用发布清单都先验签，再验证分类、列表、每类 50 项、每项 1000 字及整体 32KB 的限制。新版本日志按分类展示文本，隐藏空分类；无新版本时不展示新版本日志。旧字符串缓存作废并等待重新检查，不建立第二种协议兼容。
- `force_update` 严格使用已验签布尔值，摘要与提醒同步返回。强制更新显示警告，忽略已经保存的稍后提醒偏好，不提供跳过提示入口。更新仍通过独立权限、管理员确认、重新验签、维护备份及受控任务执行，不能自动安装、重启或因检查失败中断既有业务。应用中心列表标识只作提醒，安装确认使用重新获取的签名清单及分类日志。
- “升级记录”记录本机系统升级任务的执行结果；“更新日志”是目标发布版本的变更内容，当前接口不提供跨版本累计日志。

- `software-maintenance` 每十五秒运行固定 `software:run`。安装任务优先；空闲且已连接官网时，首次立即检查，以后默认每十二小时检查一次。`config/official_platform.php` 的 `update_check_interval_seconds` 以秒为单位，范围收敛为六至二十四小时。失败至少十五分钟后重试，运行中的检查通过持久租约避免重复请求。
- 官网响应先验证签名、实例、连接、级别、源版本、包与兼容性，再保存 `software_update` 摘要。摘要只包含可提醒的版本、日志、包摘要、成功时间等，不保存可复用的长期下载凭证。检查失败保留成功摘要，另存最近尝试时间和安全错误文案。换账号连接或运行版本改变后，旧摘要不再展示。
- 浏览器通过本机 `GET /api/admin/v1/system-updates/notice` 读取摘要，只有 `admin.updates.view` 权限的管理员可见。登录后顶部显示“发现新版本”，提供“查看更新”和“稍后提醒”；后者按管理员、当前版本和目标版本在浏览器保存二十四小时提醒偏好，新版本仍显示。后台每五分钟重新读取本机缓存，不触发官网网络检查。
- 更新页展示当前版本、最新可用版本、日志、上次成功和最近尝试时间。手动检查失败不显示“已最新”，保持旧摘要并提示失败。确认“立即更新”后服务端再次检查并验签，目标版本或摘要变化则拒绝受理，要求重新查看并确认；十分钟清单到期不影响提醒。执行进程在下载前再次获取并核验新清单。
- 没有主动推送，发现更新依赖官网发布了当前实例可用的新版本及匹配包。新提醒接口无需数据库结构迁移，使用现有加密状态表。配置及容器绑定变更需完整重启 Webman。

## 更新与恢复

任务 UUID 和目标摘要绑定，重复提交复用原任务，不能换包复用 UUID。受理、安装、账号更换或断开共用安装互斥，多个 Worker 不能同时修改运行文件。实际执行前重新取得并验证签名清单，确认版本、实例、级别、下载路径和摘要与管理员批准的一致。

包只允许白名单核心文件、不可变历史迁移和预构建资源，不覆盖 `.env`、安装身份、数据库连接设置、客户插件及上传数据。进入维护后等待短请求完成，再备份当前前缀数据库与受影响文件；长时间生产任务仍需运维在更新前排空，不能用固定等待时长证明已排空。

- 文件替换阶段失败：按文件日志恢复原文件；恢复失败保持人工恢复状态。
- 迁移开始后失败：保持维护、备份及失败原因，不自动运行旧代码或重放迁移任务。
- 文件和迁移完成：进入待重启状态；新进程核实目标代码版本、数据库版本和迁移状态后才记为成功并解除维护。
- 重启失败：记录“需要重启”，由运维完整重启后核实。
- 崩溃后执行租约过期：根据持久阶段判断是否需要人工恢复，不盲目覆盖文件。

备份保存在私有卷 `jobs/<任务UUID>/`，包含数据库、受影响文件及文件恢复日志。`recovery_required` 任务阻止后续自动安装。维护人员应先核对备份、真实文件和数据库版本，完成恢复或前向修复后通过受控维护处理任务状态；当前没有提供点击即回滚数据库的功能。

## 应用能力范围

应用中心只展示当前账号已获得的应用，提供安装、卸载及官方应用商店链接；领取和购买在官网完成，返回后刷新本机权益。本机不保存官网会员密码，也不根据回跳 URL 增加权益。

当前自动安装只开放符合 `provider` v1 契约、`permissions=[]` 的供应插件。代码 ID、版本、签名和清单必须一致，安装后为“已安装”待管理员启用。插件更新前停止接单、排空并停用，保留已有供应配置；新版本绑定仍需重新测试。新进程完成插件注册校验后才上报成功；上报失败只重试幂等报告，不重复安装。

其他插件类别和主题运行契约、应用订阅到期后的本地持续授权、插件自有数据库迁移、依赖协调、多 Worker 热切换及任意前端扩展尚未交付。签名与固定接口保证来源和接入边界，原生 PHP 仍是受信代码，不能视为恶意代码安全沙箱。
