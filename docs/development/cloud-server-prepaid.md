# 云服务器包年包月实施说明

## 当前交付范围

已落地配置、销售发布版本、计价预览、库存管理及供应参数对应；后台新增按发布版本创建购买订单、余额付款和单实例财务退款，见 [订单管理说明](order-management.md)。会员自助购买、供应商实际开通、活动/优惠券和试用办理仍待接入。

## 页面入口

- 产品管理 → 云服务器 → 线路：完整页面维护上下行范围、步长、默认和赠送、固定/累进/整档价格，以及IP范围/离散选项。防护子配置也归属于线路区域；旧网络策略不再提供编辑入口，仅保留历史读取。
- 规格：操作列「库存」按可用区配置共享总配额，NULL不限，0售罄；同一部署规格不按销售方案复制库存。
- 镜像分类可填HTTPS图标或站内路径；镜像维护默认用户名和登录端口；防护以离散资源记录及Gbps容量计价。
- 新销售方案使用v2，仅月基础价格。周期按可用区独立设置，以1～120月定义，自定义显示名；优惠为折扣基点（10000原价、8000八折）或等效计费月数，两者互斥。一次性费用不享受周期优惠。
- 销售方案设置默认存储类型/容量、每实例数据盘总上限及试用资源/容量范围。试用可限定可用区、规格、线路、镜像、存储类型、防护、单块数据盘容量和上下行带宽；防护未选时不提供附加防护。
- 交付规则 → 参数对应：配置标准字段与供应字段、必填、无损整数单位转换或枚举对应，交付预览展示实际转换结果。

## 计价和历史边界

- v1.0～v1.3仍按旧单带宽与周期读取，当前 HTTP 写入口只接受 v2；旧草稿须明确转换，历史快照不升级。
- v2用schema_version=2.0.0显式识别，发布时封存对应类型版本。旧资源的单带宽不自动猜测为上下行；未配置线路v2网络时不能发布v2。
- 发布封存线路网络、资源价格、月周期、存储、试用和供应参数规则。当前资源或交付规则修改不覆盖历史版本。
- 系统盘每台独立赠送；数据盘独立收费并同时检查全实例及各类型数量上限。
- 上行按实例向外发送，下行按实例接收。累进赠送按F(实际值)-F(min(实际值,赠送值))抵扣；整档先按实际值选档，再乘收费数量，不能因赠送降低价格档位。
- IP收费数量=max(实际-赠送,0)。防护采用离散资源选项，不接受任意客户端容量。
- 经常性费用先乘月数，再按选定周期优惠计算；一次性费用仅加一次。比例优惠按每个费用项目分别四舍五入到分，随后汇总；金额范围在乘折扣前检查，禁止整数溢出转浮点。费用明细保存原价、优惠、实付与配置事实，为交易阶段配置级活动及实例分摊提供输入。
- 白名单收敛包含嵌套磁盘/网络；密码、令牌和私钥不进入返回、销售版本或供应参数对应。

## 库存端口

接口契约见 `contracts/openapi/admin-cloud-prepaid.v1.yaml`，销售配置见 `contracts/products/cloud-server.v2.schema.json`。

后台：GET/PUT `/api/admin/v1/cloud-servers/inventory`，复用资源查看/修改权限及同源写入校验。修改携带revision，缩容不能低于预占加占用。

`ComputeInventoryRepositoryInterface`提供reserve、transition、releaseExpired。数据库唯一部署键和幂等键加行锁；锁顺序固定为库存池、预占记录。

- reserve检查数量、有效期与余量，重复同键同配置不二次计数；不存在库存配置不默认为无限。
- occupied仅从有效预占转换；晚到支付不能直接恢复过期预占。
- 正式占用只能在确认供应资源已释放时转released。
- releaseExpired重新加锁核对reserved，避免与支付转换竞争后误释放正式占用。
- 后台新订单在余额付款事务中按实例预占并立即正式占用，库存不足整笔付款回滚；未支付不预占，不需要该流程的预占过期调度。独立测试预占和其他业务预占仍需各自安排过期处理。配置页保存不会直接占用库存。
- 当前一可用区规格对应一个共享库存池，多供应资源池与自动选路需在交易阶段增加明确分配策略。

## 供应商参数规范

第三方开发者示例见[云服务器供应参数对应规范](../plugins/cloud-server-provider-mapping.md)。

只允许标准交付字段作为来源，供应目标用点路径。最多64项；目标不能重复或相互覆盖。转换支持copy/string/multiply/divide/lookup，单位转换必须能无损表达为整数。禁止动态PHP/SQL、任意表达式、密码及私钥来源。

资源external_id先使用封存的可用区映射解析。数据盘数组的复杂厂商协议由插件组装；参数预览不执行第三方请求，不代表供应商已支持生产。必填缺失、非整除、枚举未覆盖会明确失败。

## 后续交易实施顺序

1. 会员配置器与有效报价，库存/优惠券/试用额度在待支付订单事务中预占。
2. 后台已支持一单多实例及交易实付分摊；后续公共营销通过类型模块提供的标准事实匹配费用项，进一步封存活动/优惠券归属。
3. 支付成功、账务、预占转占用与Outbox在同一事务提交，Redis仅调度持久化任务。供应插件真实开通前完成能力声明、幂等及结果未知查询。
4. 试用累计配额、到期释放、转正式、续费和单实例退款；现金/赠送/优惠券以及客户退款与采购追回分开记录。
5. 按量、按流量、密钥登录通过已验签商业权益、具体实现、RBAC及供应能力共同开放。当前服务端明确拒绝。

## 社区工作台收敛（2026-10-08）

当前页面以地域和可用区、规格与套餐、线路和网络、镜像和存储、购买与计费五区组织；不再要求创建销售方案或交付规则。默认入口、并发锁、按可用区封存及历史兼容见 [工作台说明](../architecture/cloud-server-workspace-plan.md)。每项价格在资源处编辑，周期优惠统一作用于经常性费用。发布、预览不会触发订单或开通。旧 v1 网络与历史版本保留，不静默转换。

## 可用区付费周期

- `draft.zone_durations` 按 `zone_id` 保存各区的周期、名称、折扣或等效计费月数；相同月数在不同区可以采用不同优惠。购买与计费中选择当前可用区编辑，切换不丢失其他区输入。
- 后台读取旧草稿时将原全局 `durations` 独立复制给已有可用区，首次保存后采用可用区配置；新增区默认月付、季付、半年付、年付且均为原价。取消参与购买的区同时移除对应草稿周期。读取不会写数据库。
- 保存允许尚未配齐可用区，发布必须覆盖所有参与购买的可用区；重复可用区、区内重复月数、无效折扣或范围外可用区均拒绝。显式 `zone_durations` 缺少规则时不能回退到全局周期。
- 新发布封存每区周期；未选有效可用区不返回周期。切换区清理原周期并联动当前区选项，计价、订单及交付都按选中区查周期与优惠，客户端不能使用其他区的周期。
- 未包含 `zone_durations` 的旧发布版本仍读取原全局周期；修改草稿和重新发布不重算既有订单。该变更复用草稿和版本 JSON，不改表结构、不回填历史数据。

## 产品边界与清理

当前云服务器配置代码归属 compute 模块，旧销售方案/发布/交付规则 HTTP 写入口已关闭。v2 不再保存全局网络或旧网络策略，历史快照读取保留。实现与验收见[产品模块边界](../architecture/product-module-boundaries.md)。
