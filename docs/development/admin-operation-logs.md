# 管理员操作日志

## 记录范围

后台已认证的 `POST`、`PUT`、`PATCH`、`DELETE` 请求由中间件自动记录；登录和退出由登录日志负责。未认证请求不关联管理员。日志写入失败会记录服务端错误，不改变业务响应。

列表保留操作时间、操作人、操作内容、模块、状态、IP、地点和耗时。详情按需读取 HTTP 状态、请求 ID、方法、相对路径、浏览器、操作系统及有限的操作参数。权限是 `admin.page.operation-logs.view`。

## 参数与敏感信息

`request_params` 是业务审计参数，不等同于原始 URL 查询串。角色、管理员、部门写操作仅从请求体提取已列入白名单的名称、标识、状态、数据范围、关联 ID 和权限码；路径上的目标 ID 也会记录。关联 ID 和权限码超过 256 项时只记录数量提示，避免日志无界增长。描述等自由文本、密码、密钥、Cookie、认证头、原始 User-Agent、原始查询串、完整请求及响应报文均不记录。未知写接口只记录路径目标 ID，需有审计价值时再单独评估并增加字段白名单。

IP 与地点通过受信任代理规则和 ip2region 保存操作时的快照，不能用作认证或授权依据。日志详情接口仍需服务端权限校验。为控制容量和访问范围，建议按实际合同与适用法规确定保留期；维护命令 `php webman admin:prune-operation-logs --days=180` 默认只预览，加 `--execute` 才执行清理。

## 迁移

`20260926000100` 创建日志表；`20260926000200` 前向删除四个完整报文字段，旧记录中的这些内容会永久移出审计表。该迁移不可回滚，执行前必须备份并核对环境，升级后重载 Webman worker。代码与数据库迁移须在同一维护窗口完成，避免新代码访问尚未变更的结构。
