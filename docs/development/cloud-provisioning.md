# 云服务器付款与自动开通

## 当前范围

社区版支持包年包月云服务器的逐实例自动开通。付款成功表示已收款，只有供应商确认实例可用后才显示已开通。余额充值仍使用原支付通道；本次没有新增商品直接在线支付、续费、升降配或自动终止。

## 交易与交付

1. 下单由服务端重新计算价格、封存标准配置及供应映射。可选 `login_password` 单独加密保存，不进入选配、报价、普通订单快照或日志；留空由系统生成。匿名配置草稿不保存密码。
2. 余额付款在同一数据库事务内完成扣款、逐台库存占用、订单实付、服务关联及开通任务创建。供应插件不可用、连接需重新测试、绑定版本变化或任务保存失败，整笔回滚；HTTP 付款请求不调用供应商。
3. `service_provisioning_tasks` 本身是事务 Outbox，每个订单金额单元只有一个任务、一个服务及一个固定请求标识。`finance_outbox` 的付款事件仍保留给其他消费者；开通不依赖其内存分发或 Redis 入队成功。
4. `service-provisioning` 进程每五秒领取任务。订单、订单项、单位先锁定，任务再锁定；租约提交后才调用网络。180 秒租约及随机令牌阻止旧执行者覆盖新结果。
5. 首次提交意图在网络调用前写入；崩溃、超时或无有效响应后只能查询原请求。查询未找到、查到多条或收到错误响应，都不能被当作“没有创建成功”。固定主机名不是供应商端的唯一约束，宿主不会因此自动重发创建。
6. 查询退避最多五分钟，二十次未确认后进入待人工核查。成功单独关联供应实例 ID 和 IP，服务周期从实际确认开通时起算，月末按目标月最后一天钳制。每台成功或失败独立显示，不回滚已经成功的其他实例。

## 状态

| 任务 | 含义 | 后续行为 |
| --- | --- | --- |
| queued | 尚未提交 | 首次创建 |
| processing | 已被领取 | 网络执行期间持有租约，不持有数据库事务 |
| waiting | 已受理或结果不明 | 查询原请求，禁止重复创建 |
| succeeded | 供应方确认可用 | 服务 active，记录开通和到期时间 |
| failed | 明确确认没有创建 | 服务 terminated，可重试或进入原财务退款流程 |
| attention | 超时耗尽、原插件不可用或身份冲突 | 管理员核查；默认重试仍只查单 |

全部实例成功，订单 completed；全部任务结束但有失败，订单 failed；尚有待查单或待核查的实例，订单 fulfilling。逐台状态始终可以在订单详情和实例列表中查看。

## 人工处置与资金边界

- `admin.services.cloud-servers.provision` 允许重新处理失败或待核查任务，不等于确认没有资源。重试保持原请求标识；结果不明仍然只查询。
- `admin.services.cloud-servers.resolve` 独立控制“确认未开通”。管理员必须在供应商核实没有资源并填写原因；已知外部实例 ID 的任务不能使用此操作。操作由后台统一审计记录。
- 只有明确未创建、或人工核实未创建的实例可以转入未交付退款。退款仍经现有审核与财务事务，不在开通进程中自动退款。
- 结果不明、正在开通或已有供应资源的实例保持库存占用。确认失败本身也不释放库存，只有原退款流程满足全额退款条件时释放。
- 有退款金额或退款占用的单位不能重新创建，防止退款和重试竞争。开通中的实例已在付款事务内关联服务，不能被“尚未关联服务”的旧退款判断绕过。
- 供应插件和原连接配置在付款时固定。后台编辑连接不会使任务请求另一个账户；更换插件包时任务停止执行，需恢复原受审包或先核查处置。停止接单仍可处理已经接受的任务；未结束任务或存量服务阻止卸载引用插件。

## 魔方云适配

插件通过 `ProviderProvisioningInterface` 提供创建及查询方法，声明 `cloud_server.provision=true`。现有 SDK 的目录插件不必实现生产方法，也不会被误认为可自动开通。

魔方云配置增加**资源归属客户 ID**，填写魔方云中的真实客户 ID，不使用本地会员主键。实例统一归属运营方指定的上游客户；会员归属由本系统维护，本次不在上游自动注册客户。

- 登录沿用现有 `/v1/login` 解析与受限 HTTP。
- 创建使用 `POST /v1/clouds`，每次 `num=1`，固定主机名，资源使用封存的外部标识；上下行带宽、内存 MiB、系统盘和各数据盘容量按标准配置传递。
- 查询使用 `GET /v1/clouds`，宿主再次精确匹配主机名或原实例 ID；不依赖搜索条件是否被上游严格执行。分页未找到或有多个匹配，保持未知，不重复创建。`on/off/running/stopped` 且已返回购买数量的 IP 地址，才表示已确认可用；IP 未分配完整时继续查询。
- 初始密码、主机名和创建数量不允许被自定义映射覆盖。第三方原始响应、API 密钥和密码不进入客户端响应或任务错误字段。

适配按既有魔方云 v1 对接代码实现，并通过 HTTP 协议替身验证。本地测试不等于真实魔方云版本兼容或实机开通验收，上线前必须使用测试资源验证真实创建、状态查询、磁盘、IP 和密码。

## 凭据与会员查看

初始密码独立存入 `service_provisioning_credentials`。普通实例查询不包含密码，会员只能通过同源 POST 查看本人已开通实例的初始密码，响应 `Cache-Control: no-store`。前端不将密码放入 React Query、浏览器持久存储或 URL，关闭弹窗立即清空。

每台实例开通后四十八小时停止会员查看；全部任务结束后凭据四十八小时清理，已取消及全额退款订单也会清理。尚有任务未结束时，执行所需密码继续加密保留；查询不需要解密密码。过期后本次不提供初始密码恢复，也未实现供应商重置密码。

## 部署

1. 备份数据库后执行 `php webman system:migrate --force`，新增迁移 `20261018000100`。
2. 构建后台与会员控制台，并执行会员 `pnpm build:template`，交付 PC 和独立移动端主题。
3. 完整执行 `php start.php restart -d`，确认 `service-provisioning` 进程存在。
4. 魔方云内置插件升级到 1.2.0 后，在插件管理审核更新，补齐资源归属客户 ID，重新测试连接，再保存云服务器购买配置以更新绑定。不能只修改插件安装表摘要绕过审核。
5. 本次迁移不自动开通历史已付款订单，也不扫描旧数据推断是否已在供应商创建实例。历史订单必须先逐笔核查，不能直接批量补投。
