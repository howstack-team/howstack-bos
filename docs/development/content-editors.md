# 帮助文档与新闻公告编辑器

## 选择与正文格式

- 帮助文档使用 ByteMD，`body_format=markdown`；新闻公告新建使用 Tiptap，`body_format=html`。
- 两类正文均在独立编辑页面填写；列表的筛选与分页通过现有 URL 参数保留。
- 已有公告迁移后保持 Markdown，原正文不批量转换。编辑时可继续使用 ByteMD，或点击“转换为富文本”，预览并保存后才改变数据库格式。返回列表可放弃转换。
- Tiptap 使用开源 MIT 的 React、StarterKit、图片、表格、文本对齐、占位提示扩展；不使用 Pro、云服务或 CDN。HTMLPurifier 使用 LGPL-2.1，DOMPurify 使用 Apache-2.0/MPL-2.0；发行时保留依赖许可。
- 正文最大 100000 字符，数据库使用 MEDIUMTEXT，避免富文本标签和中文内容超过原 TEXT 的字节上限。摘要仍是纯文本。

## 图片

- 富文本支持链接插入及本地上传；ByteMD 支持原有图片链接插入和上传工具。
- `GET /api/admin/v1/content/{help|news}/images` 返回默认存储通道是否可用；`POST` 同路径用 multipart 字段 `file` 上传一张图片。
- 上传复用宿主 `StorageChannelService`，调用方不能指定通道或对象键。不直接写插件目录、不复制 SDK、不修改插件签名包。
- 上传要求相应内容的新增或修改权限；服务端核验实际内容 MIME、扩展名、大小与图像尺寸。允许 JPG、PNG、GIF、WebP，最大 5MiB、1600 万像素；不接受 SVG。
- 上传图片是用于公开文档的素材，具有随机的公开地址；不能用此入口上传私密附件。图片插入说明持续提示此公开属性。
- 正文保存 `/api/public/v1/content/images/{随机标识}`，不保存临时签名 URL。公共入口只查询已完成的图片引用，按原通道、修订及对象键生成 300 秒只读签名，并禁止缓存重定向。
- 结果未知保留引用，不自动重试或切换存储；尚未完成的对象不公开。返回编辑页或删除文档不会自动删除图片，避免误删被其他正文引用的素材。
- 默认通道缺失时引导配置，图片链接仍可使用。有通道查看权限才显示配置页面链接。
- 原通道修订受既有宿主约束：修改配置、归档或卸载前应先处理历史图片引用，不能将旧对象自动映射到新桶；本次不提供历史对象迁移或孤立素材清理工具。

## 保存与展示

- 保存沿用原内容新增/修改权限与分类、发布状态校验；帮助文档拒绝 HTML 格式。
- 富文本在服务端经过 HTMLPurifier 标签、属性、协议与 CSS 白名单清理；空段落、危险标签清理后的空正文不能保存。图片正文可以不含文本。
- 前端 HTML 展示使用 DOMPurify，只保留支持的正文元素与文本对齐样式；链接增加 `noopener noreferrer`。不得把未经清理的 `body` 直接传入 `dangerouslySetInnerHTML` 或 Twig `raw`。
- 消费者必须读取 `body_format`：Markdown 使用 Markdown 渲染器，HTML 使用受控富文本渲染器。不能仅根据是否出现 `<` 猜测格式。
- 迁移 `20261007000400` 为前向扩展，执行前备份；保留旧正文、新字段及图片引用，不提供删除数据的回滚。

## 验证范围

- PHP 内容权限、格式限制、HTML 清理、图片验证、上传封存和未完成对象读取拒绝。
- 独立 MySQL 中验证旧数据升级、中文注释、正文持久化、自定义前缀及失败重试。
- 浏览器 Mock 验证旧 Markdown 编辑/转换、富文本工具、图片 multipart 上传、无通道引导、预览全屏、窄屏和保存回填。
- 真实云存储上传仍需已配置的可用通道及账号验证；Mock 与隔离数据库结果不代表外部服务验收。
