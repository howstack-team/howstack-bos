# 经营分析后端接口与前端接入

## 入口和授权

- 菜单位置：总览 → 经营分析。
- 建议前端路由：`/admin/analysis`，与后台自定义入口机制一致。
- 接口：`GET /api/admin/v1/business-analysis`。
- 唯一查看权限：`admin.page.analysis.view`，权限目录分组为“总览”。该页面只读，不提供新增、编辑或删除权限。
- 此权限明确授权查看全站聚合数据；不开放客户、订单或财务明细访问，也不按管理员部门划分经营数据。仅有工作台权限不能调用此接口。角色管理能从权限目录读取此项；创始人沿用全权限规则。

本会话交付后端实现、数据库索引、契约和文档；菜单、页面和图表由前端会话接入，不修改前端源码。

## 查询参数

```http
GET /api/admin/v1/business-analysis?start_date=2026-10-01&end_date=2026-10-09&granularity=day
```

默认包含今天的最近 30 天。日期格式为 `YYYY-MM-DD`，结束日不能早于开始日或晚于系统业务时区今天，最多包含 366 天。若只传结束日期，开始日期为其前 29 天；只传开始日期，结束日期默认今天。`granularity` 为 `day` 或 `month`，只改变趋势聚合，不改变所选区间。空值、非法日期和未知粒度返回 HTTP 422，`data.errors` 对应字段错误。

日期按 `app.default_timezone` 解读，当前为 `Asia/Shanghai`；底层用 `[起日零点, 结束日次日零点)` 查询。前期区间是开始日期之前的同天数区间，不自动解释为去年同期。包含今天时，当天数据尚未完整；月粒度仅汇总选中日期覆盖的部分月份。

## 返回数据和页面建议

统一响应为 `code/message/data/request_id`，`X-Request-Id` 与正文一致。`data` 完整字段以 `contracts/openapi/admin-business-analysis.v1.yaml` 为准：

| 字段 | 用途 |
| --- | --- |
| `period` | 实际日期、前期日期、粒度、业务时区、CNY 币种和查询开始时刻 |
| `summary` | 订单实付、已完成退款、净实付、创建订单数、付费订单数、去重付费会员、新增会员、平均实付客单价 |
| `previous_summary` | 同口径、同长度前期数据；前期零值时增长率显示暂无对比，不除以零 |
| `trend` | 日或月连续趋势，缺失日期补零，升序返回 |
| `order_types` | 购买、续费、升级、试用等类型的创建数、付费数和实付金额，无数据为空数组 |
| `order_statuses` | 所选区间内创建订单的查询时状态分布，无数据为空数组 |

前端先采用日期范围、日/月切换、指标卡、实付与退款趋势、订单类型和状态分布。类型普通文本展示，金额除以 100 仅用于显示。金额字段均为整数分，净实付允许负数，不把 `0` 当空值。页面不得自动生成演示销售数据。

## 统计口径

1. **订单实付**：`orders.currency=CNY`、`paid_minor>0`、`paid_at` 落入区间，累计 `paid_minor`。后续全部或部分退款不删除原付款事实，失败履约也不抹去真实付款。当前付款流程是单次足额支付；未来多次分期支付应改为支付事件投影后更新契约，不能把此口径当作分期流水。
2. **已完成退款**：`refund_requests.currency=CNY`、`source_type=order_unit`、`status=completed`，按 `completed_at` 累计 `amount_minor`。待审核、已通过未执行、失败和拒绝退款均不计入。退款可以来自更早支付的订单。
3. **净实付**：本期实付减本期退款。不是会计收入确认、现金流或利润；充值、提现、开票金额不计入销售额，不从当前商品价格重算历史交易。
4. **创建订单**按 `created_at`，**付费订单**按 `paid_at`。两类订单可能来自不同创建区间，不能直接相除作为转化率。免费试用没有实付，不计付费订单。
5. **付费会员**按整个区间 `member_id` 去重，同一会员跨日多单只计一次。**新增会员**按会员创建时间统计，不因当前禁用状态排除。
6. **客单价**按本期累计实付除付费订单数，整数算法四舍五入到分，没有付费订单时为零。
7. 订单类型和状态分布使用查询时订单字段；没有历史状态事件账本，不能解释为过去某一日的状态快照。跨产品订单不展开订单项，避免同一订单因多实例而重复累计。

## 数据库与性能

不新建重复统计事实表，复用 `orders/refund_requests/members`。仓储执行五次有界聚合查询，覆盖当前与前期，禁止逐日期或逐订单循环访问数据库，不返回姓名、手机号、邮箱、商品配置或支付凭证。每次请求实时读取，不增加缓存刷新或统计修复操作。

新增迁移 `20261009000200_add_business_analysis_indexes.php`：

- `orders(currency, paid_at)`：CNY 付款时间窗口。
- `refund_requests(currency, source_type, status, completed_at)`：已完成实例退款窗口。

创建时间查询复用已有索引；不修改字段、中文注释、唯一索引、外键或业务记录。索引迁移按名字检测后新增，重试不重复建立；回退仅删除本迁移索引。新安装和已有库使用同一迁移。大库建立索引可能等待元数据锁，应先备份、低峰执行并监控锁等待；中断后查看迁移状态并重试，不手工删除业务记录。

通过产品命令 `php webman system:migration-status` 与 `php webman system:migrate` 执行升级，非交互模式先备份再使用 `--force`。路由、依赖和权限目录变更后 reload/restart 后端。未来体量增大时才引入可重建的日汇总投影，原交易记录仍为唯一事实来源。
