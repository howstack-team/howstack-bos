# 基础服务通道管理 v1

## 短信与邮件模板审核扩展

平台目录接口新增 `template_review.submit/query` 能力标志，依据插件实际可选接口识别。宿主提供模板提交、查询 DTO 及 `MessageTemplateReviewService` 内部调用门面，复用原通道、修订和安装包校验。提交受理与审核通过分别处理，异常保留 `unknown` 语义；普通发送不受影响。当前交付为插件接入契约，尚无审核申请表、后台提交 HTTP 操作或按钮，具体厂商按需接入。开发步骤见 [模板审核契约](../plugins/message-template-review.md)。

## 菜单与职责

系统管理 → 通道管理 → 支付通道、短信通道、邮件通道、实名认证、文件存储、第三方登录、人机验证。

页面路径为 `/admin/channels/{payment|sms|mail|identity|storage|oauth|captcha}`；自定义后台入口沿用现有路由基址。

- 应用中心管理已获得应用的安装、更新和卸载，不增加插件管理页面。
- 通道管理默认展示全部已校验的本地同类插件，未配置的插件也显示为禁用。直接点击“配置”填写商户、账号、密钥等资料，不提供“新增通道”、平台选择或自定义通道名。每个插件只允许首次配置一次，之后直接编辑及启停；未安装或包版本不匹配的平台保持可见，恢复应用状态后再配置。
- 资源供应商保持在产品管理。支付流水、实名审核、邮件发送等业务记录归属对应业务模块。
- 各类分别使用 `admin.channels.{category}.{view|update}` 权限，创始管理员按现有规则具备全部权限，普通角色须明确授权。

## 内置插件初始化与选择规则

前向迁移 `20261007000100_register_builtin_channels.php` 只登记发行包内固定清单的22个官方通道插件，完成包层安装和启用审计。插件各自的生产 Composer 依赖必须随发行包交付；不向主项目安装 SDK，不自动登记或启用任意第三方包。缺少对应目录时跳过，已有安装记录的状态、版本和摘要保持不变，包括管理员已停用或卸载的记录。真正包变更继续走受控升级流程。

初始化不创建 `channel_connections`，未配置的平台在列表中显示为禁用。登记可用包与业务配置启用分别管理，浏览列表不会产生配置记录。

| 类别 | 选择规则 | 配置页选项 |
| --- | --- | --- |
| 短信、邮件 | 可同时启用多个，设置一个主用；业务也可明确指定其他已启用配置 | 主用通道 |
| 文件存储 | 可保留多个，后续新文件上传使用默认存储；已有文件保留原通道及位置引用 | 默认存储 |
| 支付 | 多种支付方式并行，由订单支付选择 | 无统一默认 |
| 第三方登录 | 微信、QQ等登录方式并行 | 无统一默认 |
| 实名认证 | 由认证方式和业务流程指定 | 无统一默认 |
| 人机验证 | 由登录、注册等业务场景指定策略 | 无统一默认 |

列表接口返回 `default_label`，前端据此显示列和表单选项；没有类别级主用规则时为 `null`。后端同步拒绝此类请求的 `is_default=true`，返回422；不能仅隐藏前端。主用/默认配置须启用，禁用后清除当前主用关系，不自动选备用通道。历史业务绑定保留，不能因调整主用配置改变历史支付、认证或文件归属。

以上定义配置选择规则；尚未接入的具体业务流程不会因此自动调用默认存储、短信或验证插件。

## 当前交付边界

已实现七类通道的固定运行契约、配置加密、权限、审计、菜单、查询和动态表单。内置 SMTP、支付宝支付和身份验证，以及阿里云/腾讯云/赛邮/短信宝短信、阿里云/腾讯云邮件、腾讯云人脸核身、OSS/COS/七牛/本地存储、微信 Native 支付、微信网站登录和 QQ 登录，以及图像验证码、极验 4.0、网易云盾、腾讯云天御和阿里云验证码 2.0。各插件配置与能力见 [官方通道插件接入与开发](../plugins/cloud-channels.md)。

邮件沿用已有宿主发送记录和测试发送用例；其他能力提供受控内部执行门面。订单收银、公网付款回调及幂等入账、核心短信业务触发、文件业务归属、会员实名审核和第三方会员登录流程仍由对应核心业务接入。插件配置启用不能视为已完成支付、认证或会员登录。

配置适配依赖 `ChannelPlatformRegistryInterface`；注册器从已校验包和实时安装记录投影声明，不接受浏览器提交字段定义。固定入口只加载正确类别、已启用且包摘要一致的插件；历史流水封存通道修订，修订改变后停止执行并先处理原流水。

启用仅表示配置允许被后续执行用例选择；不能据此宣称外部连接成功。执行通道不做隐式故障切换，尤其支付、短信等结果未知时不得自动改用其他通道产生重复副作用。

## API 与表单

接口根 `/api/admin/v1/channels/{category}`，契约见 `contracts/openapi/admin-channels.v1.yaml`。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | 根路径 | 默认展示插件及已有配置，名称、平台、状态按 AND 组合后分页；未配置项 id/revision 为 0，configured=false |
| GET | `/platforms` | 同类别本地插件的公开配置声明和 platform_available，不输出内部包摘要 |
| GET | `/{id}` | 脱敏配置详情 |
| PUT | `/platforms/{pluginId}` | 固定插件首次配置，revision=0；同插件重复或并发首次保存返回 409 |
| PUT | `/{id}` | 编辑已有配置，需要当前 revision；名称和插件身份由后端确定 |
| PATCH | `/{id}/status` | 启停，需要当前 revision |

七类页面直接展示固定插件目录，不提供搜索表单；分页、表头状态筛选和排序保留 URL。工具栏右侧只提供带图标的刷新按钮；操作列文字链接。启用/禁用沿用 `EnabledStatus`。

连接配置通常使用单列抽屉，超过十二个动态字段加基础字段时使用完整页面，列表隐藏、保留 URL 与返回状态。字段从后端平台声明生成：文本、密码、URL、整数按钮输入框、round 开关、枚举；有单位使用 suffix，描述使用 extra。没有可用插件时保留现有配置只读，仍可禁用；未配置插件点击启用会引导填写配置，保存时可同时启用。

## 数据与一致性

- `channel_connections` 保存类别、插件身份、平台声明快照、密文、私密键名、启停、排序、备注、revision 和归档时间。
- `channel_category_settings` 初始化七行，提供类别写锁。仅短信、邮件和存储使用主用/默认引用；同类别只有一个主用连接，禁用后清空当前引用，不自动选备用。其他类别保留历史引用但不将其作为当前统一默认策略。
- 插件身份固定，首次保存受安装身份与分类行锁保护，同一个插件不会重复新增配置。既有多连接资料继续展示、可编辑及禁用，不合并、不删除，不静默切换业务绑定。乐观锁防止覆盖别人修改；保存/启用与安装状态互斥，安装身份、分类、连接按固定顺序锁定。
- 配置整体加密，不回显密文。列表不返回配置，详情只返回普通配置及私密字段是否已设置。私密空输入保留原值；清除必须显式 `clear_secrets`，必填秘密仍受校验限制。
- 曾为私密的键持续脱敏，避免插件将其改成文本字段泄漏历史值；声明快照不包含实际秘密。
- 启用通道阻止插件停用/升级，历史通道引用阻止卸载。后台不提供删除入口；保留既有连接身份、默认关系、历史引用与加密配置。
- 操作审计只允许通道名称、插件标识、状态、排序、revision 等安全摘要，不记录配置、备注、秘密值。写操作受管理员权限及同源中间件保护。

## SMTP 邮件通道

新增邮件平台的目录、配置与代码示例见 [邮件通道插件开发指南](mail-channel-development.md)。

- 系统管理 → 通道管理 → 邮件通道，在默认列表中点击“SMTP 邮件”的“配置”。可配置服务器、端口、SSL/TLS / STARTTLS / 不加密、账号认证、密码或授权码、发件邮箱与名称、回复邮箱、超时。
- 默认 SSL/TLS、465 端口、开启认证、10 秒超时；STARTTLS 通常为587端口。具体按服务商设置。开启认证时账号及密码必须填写；关闭认证允许可信本地邮件中继。域名不包含协议或端口，不支持多服务器字符串。
- SSL/TLS 与 STARTTLS 均验证证书及主机名，无关闭证书验证的配置。使用私有CA时由管理员配置PHP/OpenSSL信任库；不把CA私钥或任意证书文件上传入口交给插件。
- 保存后在操作列点击“测试发送”，填写收件邮箱即可发送固定测试内容。测试允许禁用配置，以便启用前确认；权限独立为 `admin.channels.mail.test`，并要求查看邮件通道权限。每个通道测试间隔至少30秒。
- 服务端固定 `POST /api/admin/v1/channels/mail/{id}/test`，参数为 `recipient`、`request_key`（小写UUID）、`revision`。没有匿名发送入口，不接受测试主题、正文或附件。
- `accepted` 表示SMTP服务器确认接收，不能据此宣称邮件最终进入收件箱；`failed` 为明确失败；DATA阶段断线、异常或进程中断为 `unknown`，先核查邮箱或SMTP日志，禁止自动重复发送或切换通道。
- 请求UUID持久化到 `mail_delivery_attempts`，同键同内容返回已有结果，同键不同内容拒绝；在数据库事务内领取任务，事务提交后才调用网络。正文、邮箱、密码及SMTP原始回包不保存到发送记录或操作日志。每次构造新PHPMailer，收件人、账号与连接不会跨请求共享。
- 通道配置允许改动，但执行前核对revision、平台摘要与启用状态。已经领取的发送允许收尾；后续关闭通道阻止新业务发送。网络失败不触发隐式备用通道。

### 插件与宿主边界

邮件插件只需准备三个文件，额外辅助类按需添加：

```text
plugins/mail/<id>/
├── plugin.json                 插件名称、版本、兼容范围和传输类型
├── configuration.schema.json   后台配置字段，由宿主生成表单
└── MailAdapter.php          配置校验与发送逻辑
```

1. 参考内置 SMTP 包，修改插件 ID、名称与入口命名空间，声明自己的配置字段。
2. 实现 `MailAdapterInterface` 的两个方法：

| 方法 | 输入 | 输出 |
| --- | --- | --- |
| `validateConfiguration()` | `Configuration`，当前通道配置 | 校验、补齐默认值后的 `Configuration`；不发送邮件 |
| `send()` | `MailMessage` 邮件内容、`Configuration` 通道配置 | `MailResult`，返回接收、失败或结果未知 |

`MailMessage` 提供 `recipient`、`subject`、`text`、可选 `html`，以及稳定请求键 `key` 和 `messageId()`。`Configuration::values` 提供本次配置，不包含核心模型或其他通道信息。发送方法可使用系统公共 `HttpClient` 快捷请求，也可以使用插件本地 Composer 管理的 PHPMailer 或其他 SDK：SMTP 逻辑由 SMTP 插件实现，HTTPS 邮件平台由对应插件调用自身接口；核心不按平台名字添加分支。

3. 使用 `php webman business-plugin:validate <id>` 校验包，审核后通过宿主生命周期登记、启用，在“邮件通道”配置并测试。开发者不必编写空的 `install()`、`uninstall()`、配置保存接口或后台页面。

协议统一称 v1，`mail_sdk=1.0`、能力 `mail.send=true`，网络声明为 `transport=smtp` 或 `transport=https`。第三方依赖由各插件自己的 `composer.json` 和 `composer.lock` 管理，开发者预构建生产 `vendor/` 并随插件交付、保留依赖许可证；不加入宿主 Composer，也不在客户服务器执行安装脚本。邮件插件自身负责访问管理员配置的平台、设置超时、校验证书、限制重定向和分类失败，审核及契约测试检查这些行为；`transport` 是传输声明，并不是网络沙箱。供应插件的受限 HTTP 门面仍按供应契约执行。

宿主负责配置保存与加密、权限、默认通道、包摘要、发送记录及重复请求处理。插件仅负责平台配置规则和外部发送，不访问核心模块、数据库、文件、环境变量、进程或路由；不跨调用保存凭据，不自行选择其他通道或重发结果未知的邮件。附件、模板、回调和查询投递结果尚未发布契约，不需要实现。

内置包位于 `backend/plugins/mail/smtp`，随开源发行包交付。迁移 `20261006000200_add_smtp_mail_delivery.php` 首次登记并启用该固定包，保留安装/启用事件；已有SMTP安装状态不覆盖、不自动恢复被禁用或卸载的插件。修改包文件后按现有停止接单→禁用通道→审核升级→启用流程操作，不能通过读取配置绕过包摘要验证。发行包必须完整包含该插件目录及其 Composer 锁文件、生产 vendor；宿主 Composer 不包含 PHPMailer。

宿主业务用例通过 `SendMailService::send(channelId, revision, message)` 或 `sendDefault(message)` 发单封纯文本/HTML邮件；调用方必须用稳定业务事件UUID，不能每次重试重新生成。业务发送仅允许启用通道，默认通道未配置时明确报错。模板、验证码、队列、群发及业务通知触发策略不包含在本次SMTP通道实现中。

### SMTP 验证

`SmtpMailChannelTest` 使用本地独立SMTP进程和隔离数据库，验证真实认证发送、无认证中继、SSL/TLS、STARTTLS、受信CA/不受信证书、中文及HTML MIME、收件人隔离、密码加密、权限、状态/版本、幂等、频率限制、认证失败、DATA拒绝和接收后断线。测试服务只监听loopback，不向外部邮箱投递。真实邮件服务商账号及最终收件验收仍须配置后执行“测试发送”。

2026-10-06 简化邮件入口后，独立 MySQL 回归 53 项测试、365 个断言通过，包含 SMTP、通道管理、插件生命周期、供应插件选择与静态包检查。HTTPS 邮件测试包通过 Guzzle MockHandler 验证可使用自己的配置发送，不访问外部平台；其通过不代表已接入某个真实 HTTPS 邮件服务商。

公共 HTTP 快捷客户端已开放 GET、POST、PUT、DELETE、POST 表单及通用 request，不要求普通 HTTP 通道再打包 Guzzle；第三方依赖仍按插件独立管理，不设 SDK 包名白名单。开发者指南见 [公共 HTTP 请求指南](../plugins/http-client.md)。
