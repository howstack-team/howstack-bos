# 社区版后台订单管理

## 使用流程

1. 在云服务器产品配置中完成配置并发布，启用该产品；未发布草稿不可下单。
2. 订单列表右上「创建订单」打开抽屉，选择启用会员和已发布产品。
3. 选择地域、可用区、线路、硬件分组与规格、镜像分组与镜像、磁盘、上下行带宽、IP、防护、实例数量和付费周期。可选项、组合限制及赠送配置由发布版本解析。
4. 点击「计算费用」，核对后「创建订单」。当前仅创建人民币正价购买订单，单笔不超过100万元；不手工指定价格、优惠、支付状态或实例密码。
5. 从列表「余额付款」扣除该会员余额。余额或实时库存不足时整笔付款回滚。未支付订单可取消，备注可编辑。
6. 在订单详情核对订单项和逐实例实付分摊。已付款订单可进入申请开票，实例可进入申请退款；办理前仍由财务服务重新检查资格与额度。详情切换财务操作先关闭，不叠加抽屉。

付款后订单进入交付中，并在同一事务中建立逐台服务与持久开通任务；只有供应确认可用后才标记完成。可选实例密码独立加密保存，详见 [付款与自动开通](cloud-provisioning.md)。

## 权限与安全

- 查询和每项写入均需要 `admin.page.order-list.view`；创建/配置预览/会员及产品选择另需 `.create`，付款需 `.pay`，取消需 `.cancel`，备注需 `.update`。新权限在角色权限分配中按订单管理显示，重新登录刷新授权。
- 前端隐藏未授权入口，Controller和应用层再次检查真实权限。写请求经过同源检查；不以隐藏按钮代替授权。
- 公共订单只验证购买输入的传输结构，类型专有字段通过 `ProductPurchaseInputInterface` 交给云服务器校验器白名单处理。密码、供应商参数、客户端金额状态等不进入订单配置快照。
- 参数分别使用webman validation、类型完整组合校验和服务端计价；社区模式拒绝按量、流量与密钥登录。
- 备注提交 `expected_remark`，原值变化时返回409，防止静默覆盖他人修改。查询区保持独立字段AND过滤、查询/重置、排序筛选和URL状态。

## 一致性与库存

- 固定发布版本、标准配置、供应绑定、交付配置、政策和费用分项在创建时封存。创建和计算费用重新核对发布版本是否仍可售；历史订单付款使用原快照，不追读当前调价。
- 每个实例有稳定 `order_item_units` 标识及整数分实付分摊，分摊总和等于整单应付金额。多台实例后续可分别退款、开票和关联服务。
- `order_requests` 保存管理员范围内的请求键、输入摘要和订单标识。同键同内容返回原订单；不同内容使用相同键拒绝。失败事务不会留下半成品或幂等占位。
- 待支付时不预占库存，余额付款事务中按「订单→账户→资金来源→库存池→库存记录」锁定。通过 `ProductOrderCapacityInterface` 分派库存处理，不在公共财务模块解释云规格字段。
- 每实例库存键为 `order-unit:{id}`。事务中预占立即转正式占用，无中间预占提交。库存不足、账务异常或Outbox写入失败，扣款、流水、订单状态及库存共同回滚。
- 发票与退款按订单和稳定实例顺序锁定后处理额度；全额退完某一实例后释放其占用，部分退款不释放。财务资格检查要求实例尚未开通，或关联服务已终止；已有外部资源的释放仍需后续终止流程确认，不能只修改订单状态就恢复库存。
- 创建/付款分别写入 `order.created` / `order.paid` 事务Outbox，并沿用消息场景发布。事件入库不表示供应商已执行或通知已投递。
- 历史未封存 `checkout_version=1` 的订单不自动补算或伪造库存占用，原资金分摊核实要求继续保留。

## 当前边界与扩展

当前开放后台与会员云服务器购买订单及余额付款。会员支持匿名选配、登录恢复、明确确认后下单和本人订单查询，见 [官网展示与会员购买](member-purchase.md)。零元/试用订单、续费/升级办理、购物车多产品、活动优惠券、商品订单直接在线支付及供应商终止尚未接入；逐台自动开通、结果查询和独立加密初始凭据已接入。历史订单可查询不代表这些类型都能由当前入口创建。

其他产品可新增购买输入契约、类型处理器与库存处理器，再提供对应选择界面。财务继续复用订单实例与资金来源；活动与优惠券需在创建时保存明细归属，不得退款时按当前优惠规则重算。
