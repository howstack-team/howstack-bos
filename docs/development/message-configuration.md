# 消息场景、接收组与渠道配置 v1

## 范围与入口

后台入口为「系统管理 → 消息配置」，路由 `/message-configurations`。当前交付社区版：页面分“发送给客户”和“发送给管理员”两个 Tab，表格只显示消息类型、消息描述、渠道启用状态和编辑操作。固定目录完整展示，不分页、不搜索、不刷新、不自由新增消息。

客户渠道为邮件、短信、站内消息、公众号；管理员渠道为邮件、钉钉、企业微信、飞书。注册验证码支持短信和邮件，登录验证码仍仅支持短信；此限制由统一消息目录声明，单条保存和批量配置均校验。每条消息只展示目录声明支持的渠道状态，不支持的渠道返回空值，交由全局表格缺省处理。名称和描述使用当前受众的目录元数据，工单回复不会混淆发送方向。管理员站内消息策略仍在底层保留，简化页面不覆盖它。

编辑使用单列 Drawer，URL `/message-configurations?tab=customer&edit=order_paid&channel=email` 保存受众、消息及渠道位置；抽屉 Tab 直接对应支持的渠道，只编辑开关、通道引用和模板，不显示接收组名称、组开关、范围、增删和排序。切换渠道保留输入，关闭未保存修改需确认；刷新读取已保存配置，尚无跨刷新草稿。配置保存不执行发送。

## 社区版与扩展能力

底层多接收组模型、队列、幂等、投递快照和消息日志保留。社区版通过现有场景 API 读取完整策略，按原修订保存，只合并实际编辑的普通渠道；另一受众、未触碰的渠道、组 ID、名称、顺序和范围均保留。只修改正文不会重新启用已停用的接收组；显式开启渠道才开启对应普通组。若曾明确清空某受众组，仅在实际编辑保存时补建对应普通组，读取及取消不会写入。

已有同类型多个接收组或自定义个人范围的对应渠道在简化抽屉中只读显示并提示保留，不将它们压成一个组。其他普通渠道仍可编辑。原多组独立编辑组件保留供未来扩展，但没有社区页面入口；本次没有新增商业授权或权益开关，高级页面并不等于商业版权限隔离。

## 接收组

- 每个场景最多10组，每组有稳定 ID、名称、启用开关、接收范围及自己的渠道模板。
- 关联客户：由业务事件关联会员，支持该场景声明的邮件、短信、站内消息、公众号。
- 内部人员：创始管理员或指定部门、角色、管理员，仅邮件和站内消息；只允许选择启用的系统对象。
- 群机器人：钉钉、企业微信、飞书，引用系统设置中的统一机器人，不接受逐组 Webhook 或凭据。
- 客户独有场景不能新增内部/机器人组；注册验证码可以使用关联客户的短信或邮件渠道，登录验证码只能使用短信；找回密码仍按当前目录支持邮件和短信。
- 接收组顺序可调整。范围重叠时，同一事件、同一受众账号、同一渠道只建一个任务，采用靠前组的模板；不同渠道独立投递。机器人同平台同事件仅发送一次。
- 删除或禁用接收组只影响后续事件，不修改历史任务、已读状态或已封存的模板快照。
- 组开关禁用会停止整组投递，保留原渠道开关但不要求通道可用；字段结构和模板变量仍需合法，重新启用时完整核验通道与模板；总体启用状态表示至少一个组及其渠道已启用，不表示业务已接入或最终送达。

`ticket_replied` 合并展示，但两个受众的方向不同：工作人员回复通知客户、客户回复通知内部人员。发布事件必须显式声明受众，不能因新增组把一条回复反向通知给错误的人。当前实际接入的工作人员回复只发布给客户。

配置保存本身不触发发送。消息运行时已接入订单余额付款、充值入账、管理员工单回复和实名认证审核，其余类型为预留业务事件；公众号与验证码专用发送尚未接入。所有渠道默认禁用，读取目录不插入配置记录。运行时、队列恢复及接入边界见 [消息运行时](message-runtime.md)。

“消息”指接收对象的站内消息，客户与管理员均可使用。顶栏默认读取本人真实消息，已读持久化；演示数据仅开发环境显式开启。

## 编辑字段

| 渠道 | 配置内容 |
| --- | --- |
| 邮件 | 启用、已配置的邮件通道、邮件主题、纯文本内容 |
| 短信 | 启用、已配置的短信通道、内容、厂商模板 ID、变量映射 |
| 消息 | 启用、标题、纯文本内容 |
| 公众号 | 启用、公众号模板 ID、变量映射 |
| 钉钉 | 启用、标题、内容 |
| 企业微信 | 启用、标题、内容 |
| 飞书 | 启用、标题、内容 |

邮件/短信只提供已配置、启用且平台可用的连接。启用保存时后端重新检查，并保存通道 ID 和当时的修订号；后续通道改变不能被解释为已测试连通。原连接不可用时保留引用并标明不可用，不能静默替换。没有可用邮件/短信通道时显示提醒，有对应查看权限时提供配置页面链接，否则提示联系管理员；配置完成后重新打开消息编辑即可加载可用通道。机器人未配置时同样引导到系统设置的消息通知。模板短信须填写厂商模板 ID，短信宝可使用内容字段。

钉钉、企业微信和飞书的 Webhook 与加签密钥统一放在「系统管理 → 系统设置 → 消息通知」中，路由 `/settings?tab=notifications`。每个平台配置一次，所有消息共用，消息编辑不保存凭据。机器人未配置 Webhook 时，消息不能启用该渠道；清除全局机器人不删除消息模板及其启用状态，未来发送时必须重新校验。

Webhook 只接受当前平台的固定官方 HTTPS 域名与机器人路径，不允许自定义代理、其他域名、用户信息或多余查询参数。对应平台说明：[钉钉](https://open.dingtalk.com/document/orgapp/custom-robot-access)、[企业微信](https://developer.work.weixin.qq.com/document/path/91770)、[飞书](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。配置保存不请求这些地址，运行时按已封存修订与固定官方地址执行。

## 模板与秘密

- 使用 `{{变量名}}` 占位符；每个事件返回自己的可用变量，不执行 Twig、PHP 或表达式。
- 变量映射保存为 JSON 对象字符串，例如 `{"order":"{{order_no}}"}`。最多 30 项，仅接受字符串值和当前事件允许的变量。
- 标题和模板 ID 最长 128 字符，正文 4000，变量映射 4096，Webhook 512，加签密钥 256。
- 消息配置和全局机器人均加密保存；全局机器人使用非公开系统设置键 `notifications.robots_encrypted`，只返回 `configured_secrets` 布尔标志，消息详情只返回 `robot_status`。
- 秘密空输入保持原值，替换传新值，清除通过 `clear_secrets[channel]` 明确列出字段。该操作仅用于全局机器人设置。
- 审计仅记录消息编码或设置分类与修订号，不记录模板正文、Webhook、密钥或完整请求。

## API 与权限

新场景接口契约见 `contracts/openapi/admin-message-scenes.v1.yaml`；旧受众接口仍保留兼容，见 `admin-message-configurations.v1.yaml`。统一响应为 `code/message/data/request_id`，同步返回 `X-Request-Id`。

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/api/admin/v1/message-scenes` | `admin.message-configurations.view` |
| GET | `/api/admin/v1/message-scenes/{code}` | 同上 |
| PUT | `/api/admin/v1/message-scenes/{code}` | view 与 update |
| POST | `/api/admin/v1/message-scenes/batch` | view 与 update |
| GET / PUT | `/api/admin/v1/settings/notifications` | settings 的 view / view + update |

详情只返回模板、可选通道 ID/名称、接收对象 ID/名称及机器人已配置标志；不返回联系方式、凭据或 Webhook。PUT 提交 `revisions: {customer, admin}`（只包含场景支持的受众）、`groups` 完整列表。每组提交 `id/name/kind/enabled/recipients/configurations`。各组必须包含其支持的全部渠道，后端校验模板变量、通道及范围，绑定发送通道修订。两类受众修订在同一事务内保存，任一冲突返回409并整体回滚。

新结构仍存入现有配置表的加密 JSON `_groups`。旧受众配置在读取和发送时按需映射：客户一个组、管理员拆成内部人员及群机器人组，保留原模板、引用、修订、启用状态和个人范围，机器人不会继承个人范围。读取不写库，首次新版保存写入新结构。空组列表显式禁用该受众，不能重新回退为默认组。已经保存接收组的场景拒绝旧 PUT/批量写接口并返回409，避免旧客户端覆盖新策略；旧接口只读渠道镜像不能代替接收组详情。

## 批量配置渠道

当前受众 Tab 右侧的“批量配置”是全局配置入口，直接打开短单列 Modal，不要求先勾选表格行，表格也不保留选择列。弹窗先选择渠道，再通过可搜索多选框显式选择适用消息；默认不勾选，提供“全部适用消息”选项，展示将修改的消息数量。切换渠道清空消息选择和发送通道，防止旧选择进入新渠道。

邮件/短信可选发送通道，其余渠道沿用系统设置；启用状态可保持、启用或禁用，至少实际修改一项。当前受众和渠道推导内部组类型，不要求用户理解接收组。每条适用消息必须恰有一个匹配组且该组启用；多组、缺失组或整组停用的消息不列入选择，不静默跳过已选消息，也不自动建组。保存保留正文、变量映射、范围和顺序，继续使用修订冲突及整批事务。

请求为 `items: [{code, revisions}]`、`kind`、`channel` 和可选 `channel_id/enabled`，最多30个场景，至少修改一项。按照稳定编码顺序在同一事务保存，任一修订冲突、范围非法、模板不完整或通道不可用时全部回滚，不静默跳过。保存不发消息。审计只保留场景编码、修订、渠道及开关等有限标识，禁止记录模板正文和秘密。

## 安装、升级与后续接入

迁移 `20261007000200_create_message_configurations.php` 新建带中文注释的配置表，唯一键为受众与消息编码。使用系统 `system:migration-status/system:migrate` 入口执行，不修改已发布迁移、不删现有通道连接。

迁移 `20261007000300_centralize_notification_robots.php` 增加消息通知设置分类，并合并旧管理员消息中的机器人秘密到全局加密配置，保留模板、状态和通道引用。重复执行不增加修订。若同平台历史凭据不同，迁移停止并保持原数据，须先人工统一旧配置后再升级，不能静默选取。

迁移 `20261007000700_add_message_recipient_groups.php` 为接收对象增加组标识/名称快照；保留历史任务及幂等标识，旧任务标记 `legacy`。升级前完成数据库备份；回退应用前评估新 JSON 接收组，禁止回退删除流水字段。

后续业务发送接入必须通过核心业务事件、可靠队列与幂等处理，验证消息资格、接收人及其邮箱/手机号/公众号绑定；管理员接收人和机器人权限也由核心约束。只在收到上游服务的确定结果后通知成功；结果未知的事件进入管理员异常处理。发送时重新检查通道能力和绑定修订，凭证只在后端使用，不能将本阶段“配置已启用”当作发送成功。

本模块验收覆盖真实隔离 MySQL 持久化/中文注释/多组去重/批量原子提交/并发修订、权限、模板与秘密边界，以及浏览器 Mock 的双受众列表、单列编辑抽屉、渠道切换输入保持、高级策略保留、批量操作、URL 恢复与 390px 布局。新增运行时已接入四类业务的事务；外部厂商真实发送、公众号及其余预留场景另行验收。
