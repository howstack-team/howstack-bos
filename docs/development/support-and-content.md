# 服务与内容管理

## 当前实现

运营后台的「业务管理」展示已创建的云服务器、物理服务器和服务器托管实例。「服务管理 → 工单管理」包含工单类型、工单列表和快捷回复。「内容管理」按「帮助文档」「新闻公告」分组，分别提供内容列表和分类管理。每个页面都有独立的查看权限，写操作另设权限，并由后端接口再次校验。

工单类型和快捷回复支持增删改查；工单列表支持查询、查看会话和后台回复。工单回复写入 `ticket_messages` 并将状态调整为 `waiting_member`。已有工单引用的类型不可删除。帮助文档和新闻公告共用内容表，但按 `kind` 严格隔离分类、记录和权限。帮助分类最多两级，公告分类保持一级；分类不设置业务编码。同级分类名称不能重复，不能将有子分类的一级分类改为二级分类；已有内容或子分类的分类不可删除。发布内容要求所属分类及其上级分类均已启用。

新结构由前向迁移 `20260927000500`、`20260927000600` 创建；迁移 `20260927000700` 为分类增加父级关系并移除旧编码列。执行前备份数据库，旧编码数据不会在迁移后保留。后台接口统一在 `/api/admin/v1` 下，使用管理员认证、请求校验和统一响应。帮助分类列表返回树形数据，不分页；新闻公告分类仍分页。

## 当前边界

目前尚未建设会员提交工单、工单附件、通知、自动分配和 SLA，也未开放帮助文档与公告的公开读取接口。新页面会展示数据库中的真实记录；未创建记录时为空。帮助文档和新闻公告的正文在后台使用 ByteMD 编辑与预览，接口继续保存 Markdown 原文。现有纯文本正文可继续编辑；按 Markdown 预览时，普通换行的显示可能与原先纯文本展示不同。当前没有内容图片上传接口，因此 ByteMD 不开放图片上传入口。官网公开读取及 Markdown 渲染尚未实现，后续接入时必须沿用安全的 Markdown 渲染策略，不直接输出未经清理的 HTML。

新增接口或变更权限时，同步修改 `backend/app/modules/admin/access/domain/PermissionCatalog.php`、`frontend/admin/src/routes.ts` 及对应页面操作入口。
