# PHP运行基线

最低支持PHP8.3，不限制只能使用某个8.3补丁版；本次实际验证运行时为PHP8.3.35。宿主与官方插件的Composer platform.php设置为8.3.0，仅用于保证依赖解析兼容最低基线，不伪装或替代运行时检查。发布和部署仍须执行composer check-platform-reqs。

Symfony使用7.4系列、PHPUnit使用12.5系列；高亮库使用兼容PHP8.3的2.x版本。Composer锁文件随源码交付，不能用ignore-platform-reqs绕过平台要求。安装器、插件模板与CI采用相同最低版本。管理员登录假密码哈希按运行时PASSWORD_DEFAULT生成，使8.3和更高运行时的算法及成本保持一致。

## 已有安装升级

1. 备份数据库和私有配置，检查现有支付通道是否仍有待收尾交易。处于creating/pending/unknown或七日回调窗口中的支付必须先在原运行环境收敛；不能直接覆盖其原商户插件包。
2. 部署锁定依赖；宿主运行composer install，官方插件在各自目录运行composer install --no-dev。交付包包含构建好的依赖及前端资源，客户环境不执行前端构建。
3. 通过php webman system:migrate --force执行新前向迁移20261016000100。它只认可随发行冻结的官方包旧/新摘要精确配对，保留版本、启停状态、凭据、配置修订和归档数据，不改写历史订单、发送任务或支付配置快照。非预期包或依赖差异仍须人工审核，不能自动信任。
4. 完整重启Webman及后台Worker，核对PHP版本、插件诊断、安装环境检测与登录、存储和支付回调。

PHP最低版本已统一不代表Docker生产交付已验收；现有容器的扩展、资源构建和运维要求仍需独立验证。真实商户与手机扫码验收边界继续沿用对应业务文档。

## 支付共享依赖（R05）

宿主显式锁定`guzzlehttp/uri-template`为1.0.11，与官方微信Native插件的生产依赖一致。宿主Illuminate支持1.x/2.x，但微信SDK 1.5.0只允许0.2/1.x；此前解析到2.0.1会被插件加载器拒绝。不能通过放松冲突检测修复。更新任一共享SDK前，必须同时核对宿主与插件锁文件及实际autoload，运行支付协议与真实HTTP签名回调测试，完整重启进程。此调整仍保持PHP8.3最低基线，不变更客户商户配置或历史支付快照。
