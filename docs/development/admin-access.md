# 运营后台权限与数据范围

运营后台采用固定权限目录、管理员多角色和角色数据范围。角色权限取并集；数据范围在同一次请求内取并集。没有任何启用角色的普通管理员既没有操作权限，也看不到数据。创始管理员是安装时创建的账号，拥有全部权限，不能通过管理员管理接口删除、停用或降权。

首次安装自动创建“超级管理员”系统角色和“总部”根部门，并将创始管理员分配到该角色、该部门。系统角色的权限目录随代码发布自动覆盖全部当前权限，数据范围为全部；它不能编辑、停用或删除，且只有创始管理员可将其分配给其他账号。根部门是唯一顶层节点，可以改名，但不能停用、删除或移动；新部门必须选择上级，未指定时后端默认挂在根部门下。

## 接口与前端

所有后台管理 API 位于 `/api/admin/v1`。`/auth/me` 和登录响应中的 `permissions` 是当前可用权限码，前端仅据此展示菜单、路由和操作；这不是安全边界。后端对每次 API 请求重新查询启用角色，不从 JWT 中读取权限快照。角色更新、停用或账号角色调整在下一次请求起生效。

权限码由 `PermissionCatalog` 发布，格式为 `admin.<资源>.<动作>`。目前管理员、角色和部门已经有真实接口；`admin.page.<页面键>.view` 只控制尚为 Mock 的页面访问。为客户、订单等页面新增真实 API 时，必须在后端用例中再次检查操作权限、对象归属和数据范围，不能仅复用前端菜单判断。

系统用户可设置工号 `employee_no`，最多 32 个字符；留空时保存为 `NULL`，已填写的工号在系统用户中唯一。管理员列表、详情和新增/编辑接口均返回或接受该字段。

系统用户还可设置手机号 `mobile`、邮箱 `email` 和描述 `description`，均为选填。手机号接受可带 `+` 前缀的 6–20 位数字，邮箱按邮箱格式校验；两者留空保存为 `NULL`。描述最多 255 个字符。部门可设置排序 `sort_order` 和选填描述，角色沿用已有描述并增加排序；排序范围为 0–9999，默认 0，同级部门和角色均按排序升序、再按 ID 升序显示。后台表单通过树形选择器选择部门。

数据范围包括 `all`、`department_and_children`、`department`、`self`、`custom`。管理员列表、详情和修改在 SQL 查询中应用同一范围条件；范围外对象返回 404，缺少操作权限返回 403。未来业务模块应通过自身仓储在查询、统计和导出中复用 `AdminAccessControlService::scope()` 的结果，把 `self` 对应到明确的负责人字段，不能先分页再在 PHP 中过滤。

## 旧版升级

首次安装会将安装账号标记为创始管理员并关联系统默认角色和根部门。旧库只有一个管理员时，迁移自动标记该账号并补齐关联；若有多个管理员，迁移在修改权限表之前停止，避免猜测最高权限归属。已有多个顶级部门会保留原有数据和下级关系，并统一挂到新根部门下。操作人员应先备份数据库、核对管理员 ID，再在执行迁移的同一命令环境中明确指定：

```bash
HLYQ_FOUNDER_ADMIN_ID=<已核实的管理员ID> php webman system:migrate
```

不要将此临时变量持久写入 `.env`。迁移失败后先检查 `php webman system:migration-status` 和数据库状态，不修改已发布迁移文件；必要时使用前向修复迁移。
